# AGENTS.md и CLAUDE.md: инструкции для агента внутри проекта

## 1. Зачем агенту инструкция о проекте

Когда вы открываете в редакторе чужой репозиторий, README говорит, что это за проект. Но чтобы начать работать, вам нужны и другие сведения: как собрать и запустить проект, какие команды прогоняют тесты, какой стиль кода принят, что нельзя менять.

Агент, работающий с репозиторием, оказывается в той же ситуации. Он может угадывать по названиям файлов, пробовать команды и делать выводы из ошибок — а может прочитать заранее подготовленную инструкцию, в которой проект описан в терминах действий: «собери так», «тесты запускаются так», «пиши в таком стиле».

Такую инструкцию кладут в специальные файлы проекта. Два самых распространённых имени — `AGENTS.md` и `CLAUDE.md`.

**`AGENTS.md` и `CLAUDE.md` — это Markdown-файлы в репозитории, которые описывают проект в терминах, полезных ИИ-агенту: команды, конвенции, ограничения и критерии приёмки работы.**

Файлы ничего не исполняют. Их читает окружающее приложение (агент или редактор) и добавляет содержимое в контекст модели перед работой. Как и в случае со skills, веса модели не меняются — меняется входной контекст.

## 2. AGENTS.md: открытый формат «README для агентов»

`AGENTS.md` — простой открытый формат описания проекта для кодинг-агентов. Официальный сайт формата называет его «README для агентов»: выделенное, предсказуемое место, где лежат контекст и инструкции, помогающие ИИ-агенту работать над проектом. [1]

Формат появился из совместной работы нескольких команд экосистемы: OpenAI Codex, Cursor, Amp, Jules (Google), Factory и других. Сейчас AGENTS.md развивается под руководством Agentic AI Foundation в рамках Linux Foundation. [1]

Один и тот же файл понимают десятки инструментов: GitHub Copilot, Claude Code, Cursor, Devin, Codex, Gemini CLI, Aider и другие. Не нужно отдельной версии инструкции для каждого агента. По данным сайта формата, `AGENTS.md` используют более 60 тысяч проектов на GitHub, в том числе Apache Airflow и сам OpenAI Codex. [1]

### Что обычно кладут в AGENTS.md

| Раздел | Пример содержимого |
|---|---|
| Обзор проекта | Что делает репозиторий, какие это компоненты, где что лежит |
| Команды | Установка зависимостей, запуск dev-сервера, прогон тестов |
| Стиль кода | Правила форматирования, именования, запреты |
| Инструкции по тестированию | Какие проверки пройти перед коммитом, как запустить выборочный тест |
| Особенности monorepo | Как прыгнуть в нужный пакет, как добавить зависимость в конкретный подпроект |
| Безопасность | Чего не делать, какие данные не трогать |

В больших репозиториях можно класть вложенные `AGENTS.md` в подпапки, чтобы описывать подпроекты отдельно. [1]

### Минимальный пример

```markdown
# AGENTS.md

## Команды
- Установка зависимостей: `npm install`
- Запуск dev-сервера: `npm run dev`
- Запуск тестов: `npm test`

## Стиль кода
- TypeScript в строгом режиме
- Одинарные кавычки, без точек с запятой
- Предпочитать функциональные конструкции

## Проверка перед коммитом
- Прогнать `npm test` и `npm run lint`
- Обновить тесты для изменённого кода
```

## 3. CLAUDE.md: память проекта в агентах Anthropic

`CLAUDE.md` — файл постоянной памяти проекта (project memory) в Claude Code, кодинг-агенте Anthropic. При старте сессии в папке проекта Claude Code автоматически читает `CLAUDE.md` и учитывает его содержимое, пока вы работаете в этом репозитории. [2]

Назначение — то же, что у AGENTS.md: чтобы правила и договорённости проекта переживали перезапуск сессий. В него пишут то, что агент должен знать всегда: как собирается проект, какие команды разрешены, какие проверки обязательны, какие области кода трогать нельзя.

Claude Code поддерживает несколько уровней памяти: файл политики организации, файл проекта `CLAUDE.md` в корне репозитория и пользовательский файл в `~/.claude/CLAUDE.md`. Порядок применения уровней описан в документации Anthropic. [2]

В AGENTS.md и CLAUDE.md можно подключать другие файлы: директивы импорта `@import` в CLAUDE.md и `@AGENTS.md import` в AGENTS.md позволяют разнести инструкции по подпапкам вместо одного огромного файла. [3]

### Минимальный пример

```markdown
# CLAUDE.md

## Команды
- Тесты: `python3 -m pytest tests/`
- Форматирование: `ruff format .`

## Правила
- Не менять файлы в `data/` — это исходные данные
- Денежные суммы считать через `decimal.Decimal`, не через `float`
- Перед сдачей прогнать полный набор тестов

## Ситуации
- Если тест падает не по вашей вине, сообщите об этом и продолжайте
```

## 4. Как агент узнаёт про эти файлы

Механика похожа на загрузку skills, но проще: файл находится в фиксированном месте, поэтому его не нужно искать среди множества пакетов.

1. Пользователь открывает сессию в папке проекта.
2. Приложение агента ищет `AGENTS.md` и/или `CLAUDE.md` в корне (а в некоторых инструментах — и во вложенных папках).
3. Содержимое добавляется в контекст модели, обычно в начале сессии.
4. Модель опирается на инструкцию при выборе команд и действий.

Важные следствия:

- **Это тратит токены.** Файл читается в каждой сессии, поэтому его пишут компактно. Огромный справочник лучше разнести на подключаемые файлы или вынести в документацию, которую агент читает по запросу.
- **Инструкция — не гарантия.** Агент может не выполнить шаг или выполнить его неправильно. Проверять нужно фактические действия и результат, а не наличие файла.
- **Это не скрытый промпт.** Файл лежит в репозитории — его читают и люди, и другие инструменты. Правила должны быть понятны обеим аудиториям.

## 5. Чем AGENTS.md и CLAUDE.md отличаются от README.md и от skills

| Файл / понятие | Для кого | Что содержит | Когда загружается |
|---|---|---|---|
| `README.md` | Люди | Описание проекта, быстрый старт, ссылки | По мере необходимости |
| `AGENTS.md` | Кодинг-агенты любого производителя | Команды, стиль, конвенции, ограничения | В начале сессии в проекте |
| `CLAUDE.md` | Claude Code (Anthropic) | То же, но в терминах конкретного агента и его памяти | В начале сессии в проекте |
| Skill | Агент, решающий определённый класс задач | Процедура выполнения работы: вход, шаги, правила, выход | При выборе подходящей задачи |

Разница между AGENTS.md и CLAUDE.md не в содержании, а в происхождении и экосистеме:

- `AGENTS.md` — открытый формат, который понимают многие инструменты. Его заводят, когда проект должен одинаково хорошо работать с разными агентами.
- `CLAUDE.md` — файл конкретного продукта Anthropic. Его заводят, когда команда работает в Claude Code.

Многие проекты используют оба: `AGENTS.md` для общих правил всех агентов и `CLAUDE.md` (или импорт из AGENTS.md) для деталей, специфичных для Claude Code. [3]

Связь с skills: AGENTS.md и CLAUDE.md отвечают на вопрос «как работать в этом проекте вообще», а skill — на вопрос «как выполнять этот класс задач». Skill переиспользуется между проектами, файл инструкций живёт внутри одного проекта.

## 6. Ограничения и безопасность

- **Файл не даёт прав и не создаёт инструментов.** Если в инструкции написано «запусти скрипт из базы», у агента должен быть инструмент и доступ к этой базе.
- **Неизвестный репозиторий нужно читать до запуска команд.** Как и в незнакомом skill, в AGENTS.md чужого проекта могут оказаться опасные или вредные команды. Проверяйте файл перед тем, как следовать ему.
- **Инструкция может противоречить запросу пользователя или ограничениям инструмента.** Прямой запрос и системные ограничения обычно важнее текста файла; конфликт стоит явно обсудить, а не молча выбрать одну сторону.
- **Устаревшие файлы вредят.** Формат сменился, команда переехала на другой менеджер пакетов — а агент продолжает выполнять старые команды. Инструкции нужно сопровождать вместе с кодом.

## 7. Как это связано с курсом

- AGENTS.md и CLAUDE.md — ещё один способ добавить в контекст модели структурированную инструкцию. Как и в теме skills, файл сам по себе не исполняется: инструкцию интерпретирует модель, чтение файла обеспечивает приложение.
- Компактность файла важна ровно по той же причине, что и в skills: контекст не бесплатный, в каждой сессии файлы занимают токены.
- Правила написания хорошей инструкции из `skills_intro.md` работают и здесь: вместо «будь аккуратен, делай качественно» — конкретные проверяемые шаги с критериями приёмки.
- Если инструкция требует вычислить что-то одинаково (проверить формат, посчитать сумму), то и в AGENTS.md, и в CLAUDE.md разумно сослаться на скрипт, а не описывать вычисление словами. Здесь это отдельный инструмент или команда проекта.

### Практическое задание (5 минут)

1. Откройте любой свой учебный проект из курса.
2. Напишите для него `AGENTS.md` из 3–5 разделов: команды, стиль, проверки.
3. Дайте агенту задачу в этом проекте без файла и с файлом. Сравните, сколько уточнений потребовалось и какие команды он выбирал.
4. Попробуйте добавить `CLAUDE.md`, который подключает `AGENTS.md` через `@import`, если ваш инструмент это поддерживает.
