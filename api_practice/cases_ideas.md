# Идеи кейсов для API Practice

## Формат

Каждый кейс состоит из двух частей:

1. **Файл с данными** — отдельный XML-файл. Студенты парсят через `xml.etree.ElementTree`.
2. **Ячейка ноутбука** — условие задачи + пустой кодовый блок для кода.

### Структура XML (единый шаблон)

```xml
<?xml version="1.0" encoding="utf-8"?>
<cases>
  <case>
    <id>1</id>
    <input>Текст задачи — то, что отправляем в API</input>
    <expected>
      <sentiment>negative</sentiment>
      <aspect>доставка</aspect>
    </expected>
  </case>
</cases>
```

Студенты парсят XML → берут `<input>` → отправляют в Chat Completions → сравнивают свой ответ с `<expected>` (опционально, для самопроверки).

## Блок 1: Классификация (6 кейсов)

### 1. Классификация тональности отзывов с извлечением аспектов
**Условие:** Для каждого отзыва определить: `sentiment`, `aspect`, `manager_message`.
**Файл:** `cases/block1/reviews.xml` — 20 развёрнутых отзывов интернет-магазина.
**API:** JSON-объект с тремя полями + `manager_message` — рекомендация менеджеру.

### 2. Определение тематики обращения в поддержку
**Условие:** Отнести обращение к категории: `техническая_проблема`, `оплата`, `возврат`, `другое`.
**Файл:** `cases/block1/support_tickets.xml` — 15 обращений в техподдержку.
**API:** `{"ticket_id": 1, "category": "оплата"}`.

### 3. Спам-фильтр для комментариев
**Условие:** Классифицировать комментарий: `спам`, `реклама`, `тролль`, `нормальный`.
**Файл:** `cases/block1/comments.xml` — 20 комментариев (смешанные).
**API:** `{"comment_id": 3, "label": "тролль", "reason": "..."}`.

### 4. Классификация запроса по срочности
**Условие:** Определить срочность: `critical`, `high`, `medium`, `low`.
**Файл:** `cases/block1/delivery_requests.xml` — 15 запросов в службу доставки.
**API:** `{"request_id": 5, "urgency": "high", "reason": "..."}`.

### 5. Определение языка текста
**Условие:** Определить язык (ru, en, de, tr, other) и если `other` — указать язык.
**Файл:** `cases/block1/multilingual_texts.xml` — 20 текстов на разных языках.
**API:** `{"text_id": 2, "language": "tr", "language_name": "турецкий"}`.

### 6. Сегментация клиентов
**Условие:** По описанию компании определить: `B2B`, `B2C`, `enterprise`, `startup`.
**Файл:** `cases/block1/company_profiles.xml` — 12 описаний компаний.
**API:** `{"company": "ООО Ромашка", "segment": "B2B", "confidence": 0.9}`.

## Блок 2: Перефразирование и стилизация (5 кейсов)

### 7. Перефраз в формальный стиль
**Условие:** Перевести неформальный текст в официально-деловой стиль.
**Файл:** `cases/block2/informal_letters.xml` — 10 неформальных писем и сообщений.
**API:** Переписанный текст в формальном стиле.

### 8. Упрощение сложного текста
**Условие:** Объяснить сложный текст простыми словами (как для пятиклассника).
**Файл:** `cases/block2/complex_texts.xml` — 8 технических описаний и статей.
**API:** Простое объяснение с примерами.

### 9. Адаптация под аудиторию
**Условие:** Переписать один текст для трёх аудиторий: студент, руководитель, заказчик.
**Файл:** `cases/block2/project_descriptions.xml` — 5 описаний проектов.
**API:** Три варианта текста для каждой аудитории.

### 10. Перевод с сохранением стиля
**Условие:** Перевести с русского на английский (и обратно), сохраняя профессиональный стиль.
**Файл:** `cases/block2/translates.xml` — 10 текстов для перевода (деловые, технические, юридические).
**API:** Переведённый текст.

### 11. Сокращение до лимита символов
**Условие:** Сжать текст до заданного лимита (100, 50, 20 символов), сохранив смысл.
**Файл:** `cases/block2/summaries.xml` — 10 развёрнутых текстов + поле `max_chars` в каждом.
**API:** Сжатый текст, не превышающий `max_chars`.

## Блок 3: Системный промпт — тонкий настрой (5 кейсов)

### 12. Ролевая модель влияет на стиль
**Условие:** Протестировать, как формулировка роли влияет на ответ. Сравнить: «помощник», «эксперт-юрист», «строгий рецензент».
**Файл:** `cases/block3/prompt_questions.xml` — 5 вопросов, требующих развёрнутого ответа.
**API:** Три ответа на каждый вопрос — студенты сравнивают стили.

### 13. Жёсткая структура ответа
**Условие:** Задать в `system` структуру: `Вывод:`, `Аргументы:`, `Риски:`. Проверить соблюдение.
**Файл:** `cases/block3/structured_prompts.xml` — 5 вопросов.
**API:** Ответ строго по структуре. Студенты проверяют наличие всех секций.

### 14. Ограничение длины
**Условие:** Задать лимит «не более 50 слов». Проверить на простом и сложном вопросе.
**Файл:** `cases/block3/length_limits.xml` — 8 вопросов разной сложности + поле `max_words`.
**API:** Оба ответа ≤ `max_words`. Студенты считают слова.

### 15. Многоязычный системный промпт
**Условие:** `system: "Отвечай на языке пользователя"`. Проверить на 5 языках.
**Файл:** `cases/block3/multilingual_prompts.xml` — по 4 вопроса на ru, en, de, tr, es.
**API:** Каждый ответ — на языке запроса.

### 16. Запрет слов
**Условие:** `system` с запретом на слова «очень», «довольно», «на самом деле». Сравнить ответы с/без запрета.
**Файл:** `cases/block3/word_forbids.xml` — 5 вопросов.
**API:** Два варианта ответа для каждого — студенты проверяют отсутствие запрещённых слов.

## Блок 4: Извлечение из документов (6 кейсов)

### 17. Извлечение контактных данных из резюме
**Условие:** Извлечь: имя, email, телефон, город, стек технологий.
**Файл:** `cases/block4/resumes.xml` — 10 резюме в свободном формате.
**API:** JSON: `{"name", "email", "phone", "city", "skills": [...]}`.

### 18. Извлечение событий из расписания
**Условие:** Извлечь: дату, время, название, спикер, тему.
**Файл:** `cases/block4/schedule.xml` — 15 записей из расписания конференции.
**API:** JSON-массив: `[{event, date, time, speaker, topic}, ...]`.

### 19. Парсинг реквизитов из счёта
**Условие:** Извлечь: номер, дату, ИНН, сумму, получателя, отправителя, валюту.
**Файл:** `cases/block4/invoices.xml` — 8 текстов счетов.
**API:** JSON: `{"invoice_number", "date", "inn", "amount", "currency", "payee", "payer"}`.

### 20. Извлечение метрик из отчёта
**Условие:** Извлечь: выручку, прибыль, сотрудников, динамику %, ключевые события.
**Файл:** `cases/block4/reports.xml` — 5 годовых отчётов в текстовом виде.
**API:** JSON: `{"revenue", "profit", "employees", "growth", "key_events": [...]}`.

### 21. Извлечение из юридического документа
**Условие:** Из договора: стороны, сумма, дата, срок, ответственность.
**Файл:** `cases/block4/contracts.xml` — 6 текстов договоров.
**API:** JSON: `{"party1", "party2", "amount", "date", "term", "penalty"}`.

### 22. Извлечение из рецепта
**Условие:** Извлечь: название, ингредиенты (с количествами), шаги, время, калории.
**Файл:** `cases/block4/recipes.xml` — 10 рецептов из блогов.
**API:** JSON: `{"dish", "ingredients": [{name, amount}], "steps": [...], "time", "calories"}`.

## Блок 5: Извлечение из диалогов (5 кейсов)

### 23. Анализ диалога техподдержки
**Условие:** Определить: проблему, решение, удовлетворённость, категорию.
**Файл:** `cases/block5/support_chats.xml` — 10 диалогов поддержки.
**API:** JSON: `{problem, solution, satisfaction, category, follow_up}`.

### 24. Action items из совещания
**Условие:** Извлечь: кто, что, дедлайн, приоритет.
**Файл:** `cases/block5/meetings.xml` — 8 транскриптов планёрок.
**API:** JSON: `[{"person": "...", "action": "...", "deadline": "...", "priority": "..."}, ...]`.

### 25. Извлечение из интервью
**Условие:** Извлечь: вопрос, ответ, тема, ключевая цитата.
**Файл:** `cases/block5/interviews.xml` — 5 текстов интервью.
**API:** JSON: `[{"question": "...", "answer": "...", "topic": "...", "quote": "..."}, ...]`.

### 26. Анализ чат-бота
**Условие:** Определить: частые темы, незакрытые вопросы, фрустрацию, рекомендации по улучшению.
**Файл:** `cases/block5/bot_conversations.xml` — 10 диалогов с чат-ботом.
**API:** JSON: `{topics: [...], unresolved: [...], frustration_level: "low/medium/high", suggestion: "..."}`.

### 27. Извлечение фактов из новостей (5W)
**Условие:** Из статьи извлечь: who, what, where, when, why.
**Файл:** `cases/block5/news_articles.xml` — 10 новостных статей.
**API:** JSON: `{who, what, where, when, why}`.

## Блок 6: Комбинированные / продвинутые (3 кейса)

### 28. Классификация → извлечение → ответ
**Условие:** Прочитать обращение: определить категорию, извлечь ключевые данные, сформировать шаблонный ответ.
**Файл:** `cases/block6/combo_tickets.xml` — 10 обращений.
**API:** JSON: `{category, extracted_data: {...}, suggested_response: "..."}`.

### 29. Цепочка извлечений из разных типов документов
**Условие:** Загрузить 2-3 разных типа документов, извлечь из каждого нужный формат. Показать, как меняется `system`.
**Файл:** `cases/block6/mixed_documents.xml` — по 3 документа каждого типа (резюме, счёт, расписание).
**API:** Разные JSON-форматы в зависимости от типа. Студенты определяют тип и применяют промпт.

### 30. Свободный кейс «свой сценарий»
**Условие:** Придумать свой кейс: загрузить файл с данными → написать промпт → обработать.
**Файл:** Студенты создают свой `.xml`-файл.
**API:** Зависит от идеи.
