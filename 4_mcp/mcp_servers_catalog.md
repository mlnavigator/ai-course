# Каталог готовых MCP-серверов

Дополнение к материалу о MCP и практикуму на Python. Дата проверки источников: **20 октября 2026 года**.

MCP-сервер не обязательно писать самостоятельно. Для файлов, браузера, баз данных, документации и внешних сервисов есть готовые реализации. Их можно подключить к совместимому агенту или вызвать обычным MCP-клиентом.

Ниже — четыре места для поиска и двадцать один сервер с примерами учебных задач, многие из них — готовые реализации на Python. Возможности и требования сверены с документацией проектов; установка всех перечисленных серверов в рамках подготовки каталога не проверялась.

## 1. Где искать серверы

| Каталог | Что в нём искать |
|---|---|
| [Официальный MCP Registry](https://registry.modelcontextprotocol.io/) | Опубликованные MCP-серверы и сведения о подключении. Основная отправная точка. |
| [Awesome MCP Servers](https://github.com/punkpeye/awesome-mcp-servers) | Подборка по категориям: разработка, данные, браузеры, внешние сервисы. Удобна для знакомства с разнообразием интеграций. |
| [Smithery](https://smithery.ai/) | Каталог и платформа подключения серверов к сервисам. Условия использования зависят от выбранной интеграции. |
| [Reference Servers](https://github.com/modelcontextprotocol/servers) | Набор эталонных реализаций от проекта MCP. Полезен для изучения устройства серверов и SDK. |

Официальный Registry — реестр, а не проверка качества каждого опубликованного сервера. Reference Servers — учебные реализации, не заявленные как готовые промышленные решения.

## 2. Файлы, локальный репозиторий и память

### Filesystem

**Проект:** [modelcontextprotocol/servers — Filesystem](https://github.com/modelcontextprotocol/servers/tree/main/src/filesystem).

- **Возможности:** чтение, поиск и изменение файлов в разрешённых каталогах.
- **Что подготовить:** отдельную учебную папку; ключ внешнего сервиса не нужен.
- **Пример задачи:** «Изучи файлы проекта. Составь описание структуры и сохрани его в `project_overview.md`».
- **Что проверить:** агент действительно прочитал файлы; описание соответствует содержимому; результат сохранён в указанном месте.

### Git

**Проект:** [modelcontextprotocol/servers — Git](https://github.com/modelcontextprotocol/servers/tree/main/src/git).

- **Возможности:** просмотр истории и изменений, работа с локальным Git-репозиторием.
- **Что подготовить:** Git и учебный репозиторий с несколькими коммитами. Аккаунт GitHub не нужен.
- **Пример задачи:** «Сравни два последних коммита. Объясни изменения и перечисли затронутые функции».
- **Что проверить:** ответ опирается на diff, а не только на сообщения коммитов.

### Memory

**Проект:** [modelcontextprotocol/servers — Memory](https://github.com/modelcontextprotocol/servers/tree/main/src/memory).

- **Возможности:** сохранение сущностей, фактов и связей в графе знаний.
- **Что подготовить:** постоянное хранилище сервера; ключ внешнего сервиса не нужен.
- **Пример задачи:** «Сохрани сведения о компонентах проекта и их зависимостях. В новой сессии найди компоненты, связанные с базой данных».
- **Что проверить:** сведения восстановлены через инструменты сервера. Само подключение Memory не означает, что агент автоматически запоминает каждый разговор.

## 3. Веб-страницы и браузер

### Fetch

**Проект:** [modelcontextprotocol/servers — Fetch](https://github.com/modelcontextprotocol/servers/tree/main/src/fetch).

- **Возможности:** получение содержимого веб-страницы и преобразование в удобный для модели текст.
- **Что подготовить:** доступный URL; для обычной открытой страницы ключ сервиса не нужен.
- **Пример задачи:** «Прочитай документацию по этой ссылке и выдели требования к установке».
- **Граница применения:** Fetch получает известный URL. Он не заменяет поисковик и браузер, выполняющий действия на странице.

### Playwright MCP

**Проект Microsoft:** [microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp).

- **Возможности:** управление браузером — переходы, нажатия, заполнение форм, проверка состояния страницы.
- **Что подготовить:** Node.js и браузер согласно инструкции проекта. Отдельный API-ключ не требуется.
- **Пример задачи:** «Открой локальный сайт, заполни форму регистрации тестовыми данными и проверь сообщение об успешном завершении».
- **Что проверить:** форма действительно отправлена; агент проверил результат действия.

Подходит для демонстрации того, как агент взаимодействует с уже существующим интерфейсом, даже если у приложения нет отдельного MCP-сервера.

### Chrome DevTools MCP

**Проект:** [ChromeDevTools/chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp).

- **Возможности:** просмотр консоли и сетевых запросов, скриншоты, анализ производительности, автоматизация действий в Chrome.
- **Что подготовить:** Chrome и Node.js согласно инструкции проекта.
- **Пример задачи:** «Открой страницу с ошибкой загрузки данных. Найди сбой по консоли и сетевым запросам».
- **Что проверить:** названы конкретный запрос, код ответа или ошибка JavaScript, подтверждающие вывод.

Playwright удобно показывать на пользовательском сценарии, Chrome DevTools — на технической диагностике страницы.

## 4. SQL, данные и документы

### DBHub

**Проект Bytebase:** [bytebase/dbhub](https://github.com/bytebase/dbhub).

- **Возможности:** доступ к SQLite, PostgreSQL, MySQL, SQL Server, MariaDB и Oracle.
- **Что подготовить:** файл SQLite или параметры подключения к СУБД. Для учебной SQLite внешний аккаунт не нужен.
- **Пример задачи:** «Исследуй схему магазина и посчитай выручку по оплаченным заказам за указанный период».
- **Что проверить:** использованы правильные таблицы, цены продажи и статусы; JOIN не завысил число заказов.

Для курса удобно подключить ту же `shop.db`, для которой студенты писали собственный MCP-сервер. Сравните готовый интерфейс работы с БД и предметные инструменты `get_order` и `sales_summary`.

Эталонные SQLite и PostgreSQL серверы из старых подборок проекта MCP перенесены в [архив](https://github.com/modelcontextprotocol/servers-archived). Их можно изучать как исходный код, но для нового упражнения с готовым сервером в этом каталоге выбран DBHub.

### Postgres MCP Pro

**Проект:** [crystaldba/postgres-mcp](https://github.com/crystaldba/postgres-mcp).

- **Возможности:** чтение схемы и данных PostgreSQL, выполнение SQL, анализ планов запросов и подсказки по индексам.
- **Что подготовить:** Python или Docker и параметры подключения к учебной базе Postgres. Отдельный внешний аккаунт не нужен.
- **Пример задачи:** «Изучи схему учебной базы, найди медленные запросы и предложи, какие индексы добавить».
- **Что проверить:** ответ основан на реальной схеме и плане запроса, а не на предположениях; изменения данных выполняются только там, где это явно разрешено.

Установка: `pip install postgres-mcp` и запуск `postgres-mcp`, либо `docker pull crystaldba/postgres-mcp`. Сервер поддерживает SSE-транспорт (`--transport=sse`), поэтому один запущенный сервер могут использовать несколько клиентов.

Рядом с DBHub это полезно для сравнения: сервер на Python умеет не только отвечать на вопрос по данным, но и анализировать, как устроены сами запросы.

### DuckDB / MotherDuck MCP

**Проект:** [motherduckdb/mcp-server-motherduck](https://github.com/motherduckdb/mcp-server-motherduck).

- **Возможности:** аналитические SQL-запросы к локальной DuckDB (файлы CSV, Parquet) и к облачной MotherDuck.
- **Что подготовить:** Python и пакет сервера; для локального файла отдельный ключ не нужен.
- **Пример задачи:** «Загрузи CSV с продажами в DuckDB и посчитай выручку по месяцам и категориям».
- **Что проверить:** агрегаты не завышены — GROUP BY и JOIN дают корректные суммы, результат соответствует таблице.

Установка: `pip install mcp-server-motherduck`, запуск `mcp-server-motherduck --db-path путь/к/файлу.duckdb`.

DuckDB читает CSV и Parquet файлы напрямую, поэтому студенту не нужен предварительный импорт данных в «большую» базу.

### MarkItDown MCP

**Проект Microsoft:** [microsoft/markitdown — MCP](https://github.com/microsoft/markitdown/tree/main/packages/markitdown-mcp).

- **Возможности:** преобразование документов в Markdown для последующего анализа агентом.
- **Что подготовить:** Python, пакет MCP-сервера и зависимости нужных конвертеров. Обычная локальная конвертация не требует ключа модели; дополнительные возможности могут иметь свои требования.
- **Пример задачи:** «Прочитай DOCX с описанием проекта и презентацию. Найди расхождения в сроках и составе функций».
- **Что проверить:** извлечение не потеряло значимые таблицы или фрагменты. Для первого опыта возьмите документы с текстом, а не сканы.

## 5. Векторный поиск и память агентов

### Chroma MCP

**Проект:** [chroma-core/chroma-mcp](https://github.com/chroma-core/chroma-mcp).

- **Возможности:** поиск похожих текстов по векторным представлениям, создание и работа с коллекциями Chroma.
- **Что подготовить:** Python и пакет сервера; для первых опытов подойдёт встроенное in-memory хранилище. Модель эмбеддингов Chroma умеет работать локально, поэтому ключ внешнего сервиса не обязателен.
- **Пример задачи:** «Загрузи описания модулей курса в векторную коллекцию и найди три ближайших по смыслу описания к задаче из практикума».
- **Что проверить:** результаты реально отсортированы по близости (метрика), а не просто повторяют запрос.

Установка: `pip install chroma-mcp`, запуск `python -m chroma_mcp.server`.

Chroma — открытая векторная база данных. Удобно показать, чем поиск по смыслу отличается от поиска по ключевым словам.

### Mem0 (долговременная память)

**Проект:** [mem0ai/mem0-mcp](https://github.com/mem0ai/mem0-mcp).

- **Возможности:** сохранение, поиск и обновление фактов о пользователе, чтобы агент помнил их между сессиями.
- **Что подготовить:** доступ к сервису памяти Mem0 (ключ API; облачный сервис, у бесплатного тарифа есть лимиты). Вариант-шаблон [coleam00/mcp-mem0](https://github.com/coleam00/mcp-mem0) можно запустить локально и использовать как основу для собственного сервера на Python.
- **Пример задачи:** «Запомни интересы студента из разговора. В новой сессии предложи тему следующего практикума с учётом этих интересов».
- **Что проверить:** сохранённый факт найден инструментами сервера. Память живёт в отдельном хранилище сервера, а не в настройках модели.

Открытый код MCP-сервера не означает бесплатный доступ к API, которое он вызывает. Ключ внешнего сервиса также не заменяет ключ модели: это разные подключения.

### Atlassian (Jira и Confluence)

**Проект:** [sooperset/mcp-atlassian](https://github.com/sooperset/mcp-atlassian).

- **Возможности:** поиск и создание задач Jira, смена их статусов, чтение и поиск страниц Confluence.
- **Что подготовить:** адрес инстанса Atlassian и учётные данные: email и API-токен для Cloud либо токен для Server/Data Center.
- **Пример задачи:** «Собери открытые задачи проекта по указанному фильтру и подготовь короткий статус-отчёт».
- **Что проверить:** в ответе — реальные ключи задач, статусы и ссылки, а не выдуманные данные.

Установка: `pip install mcp-atlassian`. Хороший пример «сервера-интеграции»: поверх публичного API Atlassian он даёт около 80 инструментов. Работает для Cloud и Server/Data Center.

## 7. Безопасное выполнение кода и мониторинг

### E2B (безопасное выполнение кода)

**Проект:** [e2b-dev/mcp-server](https://github.com/e2b-dev/mcp-server).

- **Возможности:** выполнение Python и JavaScript в изолированной облачной песочнице, работа с файлами внутри неё.
- **Что подготовить:** аккаунт E2B и API-ключ (есть бесплатный тариф).
- **Пример задачи:** «Выполни сгенерированный скрипт в песочнице, покажи вывод и сохрани получившийся файл».
- **Что проверить:** код реально выполнен в изолированной среде; вывод или файл получены. Код, сгенерированный моделью, — типичный кандидат для такой песочницы.

### Sentry MCP

**Проект:** [getsentry/sentry-mcp](https://github.com/getsentry/sentry-mcp).

- **Возможности:** поиск ошибок и трассировок в Sentry, чтение отчётов об ошибках и данных производительности.
- **Что подготовить:** токен Sentry и доступ к организации и проектам.
- **Пример задачи:** «Найди последние ошибки учебного приложения, объясни причину по стектрейсу и предложи исправление».
- **Что проверить:** названы конкретные событие, ошибка и место в коде, а не общее описание.

Установка: `pip install sentry-mcp`.

## 8. Простой сервер для обучения

### Time (mcp-server-time)

**Проект:** [modelcontextprotocol/servers — Time](https://github.com/modelcontextprotocol/servers/tree/main/src/time).

- **Возможности:** текущее время и часовой пояс по IANA-зонам, перевод времени между поясами.
- **Что подготовить:** Python, пакет `mcp-server-time`; ключ не нужен.
- **Пример задачи:** «Который сейчас час в указанном часовом поясе? Переведи время встречи из одного пояса в другой».
- **Что проверить:** модель использует инструменты сервера, а не предполагает время по своему опыту.

Хороший первый сервер для знакомства: ставится за минуту и не требует ключей. На нём удобно показать, чем инструменты MCP отличаются от знаний модели.

Перед подключением проверьте в README проекта:

1. Как запускается сервер: локальная команда или удалённый URL.
2. Какой транспорт поддерживается: stdio или Streamable HTTP.
3. Нужны ли аккаунт, ключ, браузер или доступ к БД.
4. Какие инструменты только читают, а какие меняют данные.

Для учебных опытов используйте отдельную папку, тестовый репозиторий и копию БД. Название инструмента и его описание не заменяют реальные ограничения доступа.

## 10. Задание: подключить готовый сервер

Выберите один сервер из каталога и выполните три операции через MCP. Для начала подойдут Filesystem, Playwright, DBHub или Time; из новых серверов удобны Postgres MCP Pro и DuckDB/MotherDuck.

### Порядок работы

1. Подключите сервер по инструкции проекта.
2. Получите список tools и изучите схемы аргументов.
3. Выполните обычную задачу и сохраните результат.
4. Проверьте пограничный случай: отсутствующий объект, пустой результат или неверный параметр.
5. Объясните, какую интеграцию сервер реализует за вас.

### Что показать

- Ссылку на сервер, установленную версию и способ подключения.
- Названия выбранных tools и переданные аргументы.
- Фактические результаты вызовов.
- Краткий ответ: что пришлось бы писать самостоятельно без этого сервера.

Если использовался агент, приложите вызовы инструментов, а не только итоговый текст. Без агента работу можно выполнить MCP-клиентом на Python.

### Дополнение к практикуму с SQLite

Подключите DBHub к учебной `shop.db`. Задайте одну и ту же задачу через готовый сервер и через самостоятельно написанный сервер:

> Найди оплаченные заказы за период, посчитай их количество и общую сумму.

Сравните доступные инструменты, число вызовов, объём возвращённых данных и ошибки. Предметный tool с готовым SQL и универсальный доступ к БД решают разные задачи: первый фиксирует конкретную операцию, второй даёт больше свободы при исследовании данных.
