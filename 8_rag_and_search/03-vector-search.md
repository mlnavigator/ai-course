# 3. Векторный поиск: эмбеддинги, kNN и векторные базы

Материал для курса по ИИ. Все примеры — Python. Модели и API сверены с документацией 30 октября 2026 года.

**Цель:** разобраться, откуда берётся вектор текста, как находят соседей и какую роль играет векторная БД. Код: `dense.py` и `vector_db.py` в общем проекте.

## 1. Зачем нужен ещё один способ поиска

Лексический поиск сопоставляет термы после анализа текста. Запрос «не помню секретное слово для входа» может не найти короткую инструкцию «Восстановление пароля», если нет общих слов и словаря синонимов.

**Embedding-модель преобразует текст в числовой вектор, обученный отражать определённые отношения между текстами.** Поиск находит документы, чьи векторы близки вектору запроса.

Это статистически обученное представление, а не точное кодирование смысла. Близкими могут оказаться фразы с противоположным утверждением или разные коды ошибок из одной темы. [1]

## 2. Как текст превращается в вектор

Для типичного encoder-подхода:

1. Токенизатор разбивает текст на токены и выдаёт их ID.
2. Transformer вычисляет контекстные представления токенов.
3. Pooling объединяет их в один вектор фрагмента.
4. При необходимости вектор нормируется по длине.

Pooling бывает разным. Нельзя взять произвольную модель, усреднить её скрытые состояния и предположить, что получится качественный поисковый эмбеддинг. Важны обучение, используемый слой, pooling и инструкция модели.

Модели retrieval обычно учатся сближать запрос с релевантным фрагментом и отделять от нерелевантных, в том числе похожих по теме «сложных отрицательных» примеров. Обучение на парафразах и обучение на парах «вопрос — отвечающий фрагмент» решают близкие, но не одинаковые задачи.

### Bi-encoder

Запрос и документ обрабатываются раздельно:

\[
u=f_q(q),\quad v=f_d(d),\quad score=sim(u,v).
\]

Веса двух ветвей могут быть общими. Разделение может задаваться префиксами или инструкциями. Основное преимущество: векторы документов вычисляются заранее; при запросе нужно вычислить только вектор запроса и сравнить его с индексом.

Если одну модель заменить другой, старые векторы перестают быть совместимыми. Даже два вектора размерности 384 могут относиться к совершенно разным координатным пространствам.

## 3. Небольшие мультиязычные модели с Hugging Face

Для основного проекта выбран E5-small. Вторая модель — компактный baseline для эксперимента, а не утверждение о равном качестве поиска.

| Модель | Примерный размер | Вектор | Длина входа | Особенность |
|---|---:|---:|---:|---|
| [intfloat/multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small) | ≈118 млн параметров | 384 | До 512 токенов | Для retrieval; `query: ` и `passage: `, включая русский |
| [sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2) | ≈118 млн параметров | 384 | В конфигурации Sentence Transformers — 128 токенов | Мультиязычная близость предложений; специальные E5-префиксы не нужны |

E5 заявляет поддержку широкого набора языков, MiniLM — 50 языков; русский входит в область применения обеих моделей. Заявление о мультиязычности не гарантирует одинаковое качество на всех языках и в вашей предметной области. Данные о форматах входа и длине взяты из model cards и конфигураций. [2–4]

В контрольном запуске у E5-small посчитано 117 653 760 параметров. Размер около 118 млн параметров означает примерно `118·10^6·4 ≈ 472 MB` **только весов FP32**, или около 450 MiB. Реальный расход памяти больше: токенизатор, активации, библиотеки, батч и сами векторы. Это расчёт по числу параметров, не измерение RSS или VRAM.

Обе модели можно запускать на CPU. GPU ускоряет пакетную индексацию, но не обязателен для маленькой лабораторной. Не следует переносить скорости из чужого benchmark на свой процессор.

## 4. Первый пример: E5 и точный поиск

Установка в отдельном окружении:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install sentence-transformers numpy
```

На Windows PowerShell используйте `.venv\Scripts\Activate.ps1`. На первом запуске библиотека скачивает веса с Hugging Face. Установка PyTorch и ускорителей зависит от платформы; для лабораторной достаточно CPU.

Самостоятельный пример:

```python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('intfloat/multilingual-e5-small', device='cpu')
texts = [
    'Для восстановления пароля нажмите ссылку на странице входа.',
    'Доставка по городу занимает два рабочих дня.',
    'Деньги возвращаются на исходную банковскую карту.',
]
x = model.encode(
    ['passage: ' + text for text in texts],
    normalize_embeddings=True,
    convert_to_numpy=True,
)
q = model.encode(
    ['query: Я забыл данные для входа'],
    normalize_embeddings=True,
    convert_to_numpy=True,
)[0]
scores = x @ q
for i in np.argsort(-scores):
    print(float(scores[i]), texts[i])
```

Векторы документов `x` имеют форму `(3, 384)`, запрос `q` — `(384,)`, scores — `(3,)`. Этот код вычисляет сходство со всеми документами. Векторная БД здесь не используется.

Выбор русского текста не меняет английские служебные префиксы E5. Если библиотека или интеграция сама добавляет prompt, следите, чтобы префикс не появился дважды. В проекте префиксы добавляются явно через `encode`. [2]

## 5. Метрики близости

Косинусное сходство:

\[
\cos(u,v)=\frac{u\cdot v}{\|u\|_2\|v\|_2}.
\]

Скалярное произведение:

\[
u\cdot v=\sum_i u_i v_i.
\]

Евклидово расстояние:

\[
\|u-v\|_2=\sqrt{\sum_i(u_i-v_i)^2}.
\]

Для единичных векторов:

\[
\|u-v\|_2^2=2-2(u\cdot v),\qquad u\cdot v=\cos(u,v).
\]

Поэтому после L2-нормировки максимальный cosine, максимальное скалярное произведение и минимальное L2-расстояние дают одинаковый порядок с точностью до численных погрешностей и равных scores. Без нормировки скалярное произведение учитывает также длины векторов.

Для проверки математики без скачивания модели:

```python
import numpy as np

x = np.array([[1., 0.], [0., 1.], [-1., 0.]])
q = np.array([1., 0.])
print(x @ q)                       # [1., 0., -1.]
print(np.sum((x - q) ** 2, axis=1)) # [0., 2., 4.]
```

Реальные эмбеддинги нельзя интерпретировать как «первая координата — доставка, вторая — деньги». Смысл распределён по координатам; числовая близость зависит от обучения модели.

## 6. kNN и ANN

**kNN-поиск** — задача найти k ближайших объектов по заданной метрике. Здесь это не классификатор k-nearest neighbors, хотя тот использует похожую операцию.

**Exact search** вычисляет точный top-k для заданных векторов. Полный перебор требует порядка `N·d` операций для сходств, где `N` — число фрагментов, `d` — размерность. Полная сортировка добавляет `N log N`; частичный отбор позволяет не сортировать всё.

**ANN — Approximate Nearest Neighbor search:** ускоряет поиск, допуская пропуск части истинных ближайших соседей. «Точный» здесь относится к геометрии выбранных векторов, а не к истинной релевантности текста.

| Метод | Идея | Компромисс |
|---|---|---|
| Полный перебор | Сравнить со всеми векторами | Простота и точность; стоимость растёт с корпусом |
| HNSW | Искать путь по многослойному графу соседей | Быстрый запрос; дополнительная память и настройки |
| IVF | Разбить пространство на области, искать в части областей | Пропуски при слишком узком обходе |
| Квантизация | Хранить приближённые значения векторов | Меньше памяти, возможна потеря качества |

HNSW использует верхние уровни для крупного перемещения, а нижние — для уточнения соседей. Чем шире поиск, тем обычно выше полнота геометрического top-k и больше задержка. Конкретные названия параметров зависят от движка. [5]

**Не путайте две метрики:** ANN Recall@k сравнивает выдачу с точным векторным top-k; retrieval Recall@k сравнивает её с человеческой разметкой релевантности. Идеальная первая метрика совместима с плохой второй.

### Тот же точный kNN через scikit-learn

После вычисления `x` и `q` из раздела 4 можно использовать готовый интерфейс соседей:

```python
from sklearn.neighbors import NearestNeighbors

index = NearestNeighbors(metric='cosine', algorithm='brute')
index.fit(x)
distances, indices = index.kneighbors(q.reshape(1, -1), n_neighbors=3)
for distance, i in zip(distances[0], indices[0]):
    print(float(distance), texts[i])
```

Здесь возвращается cosine distance: меньше — лучше. Для ненулевых векторов она равна `1 - cosine_similarity`. `algorithm='brute'` явно задаёт полный перебор. Это интерфейс поиска соседей, а не обучение семантической модели.

## 7. Что делает векторная база

Векторная БД хранит записи вида «ID + вектор + payload» и предоставляет операции записи, поиска, фильтрации и удаления. Embedding-модель вычисляет вектор; сама БД обычно ищет среди уже вычисленных векторов. Автоматическая векторизация, если она есть, является отдельной интеграцией.

| Уровень | Пример роли |
|---|---|
| NumPy | Матрица векторов и точный поиск в процессе Python |
| Библиотека индексов, например FAISS | Алгоритмы векторного поиска без полного набора функций БД |
| Векторная БД, в примере Qdrant | Коллекции, ID, payload, запросы и фильтры |
| Реляционная БД с векторным расширением | Совмещение SQL-данных и векторов |

Это категории архитектуры, а не рейтинг продуктов. Для 12 записей отдельный сервер избыточен; локальный режим позволяет изучить API БД без инфраструктуры.

## 8. Qdrant local mode на Python

```bash
python -m pip install qdrant-client
```

QdrantClient поддерживает `:memory:` для RAM и `path=...` для локального хранения. Этот режим полезен для разработки, но не заменяет проверку поведения и производительности серверной установки. [6]

Ниже полностью автономный пример на синтетических векторах. Они нужны только для проверки API, не кодируют смысл текста:

```python
from qdrant_client import QdrantClient, models

client = QdrantClient(':memory:')
client.create_collection(
    collection_name='demo',
    vectors_config=models.VectorParams(size=2, distance=models.Distance.COSINE),
)
client.upsert(
    collection_name='demo',
    points=[
        models.PointStruct(id=1, vector=[1., 0.], payload={'lang': 'ru', 'text': 'A'}),
        models.PointStruct(id=2, vector=[0., 1.], payload={'lang': 'en', 'text': 'B'}),
    ],
    wait=True,
)
result = client.query_points(
    collection_name='demo',
    query=[1., 0.],
    query_filter=models.Filter(must=[
        models.FieldCondition(key='lang', match=models.MatchValue(value='ru')),
    ]),
    limit=2,
    with_payload=True,
).points
for point in result:
    print(point.id, point.score, point.payload)
client.close()
```

Для поиска по реальным эмбеддингам E5 запустите `python vector_db.py`. В нём в payload сохраняются ID, язык, заголовок и исходный текст.

Локальная демонстрация **не измеряет HNSW**. В серверной БД выбор индекса и плана поиска зависит от размера коллекции, фильтров и настроек. В Qdrant есть и векторные, и payload-индексы: индекс по метаданным помогает фильтрации, а не создаёт текстовые эмбеддинги. [7]

## 9. Фильтры: до или после поиска

Если разрешены только документы группы поддержки, это условие должно учитываться в поиске. Выбор top-10 по всей базе с последующим удалением запрещённых документов может оставить ноль результатов, хотя в разрешённой части хорошие документы есть.

Фильтр `lang='ru'` в примере демонстрирует механизм, но для мультиязычного поиска он может вредить: русский вопрос способен иметь ответ в английском документе. Фильтровать язык нужно по требованиям продукта, а не автоматически.

Payload-фильтр не заменяет авторизацию. Приложение обязано вычислять доступные группы из проверенного контекста пользователя, а не принимать произвольный `access_group` от клиента.

## 10. Память и обновления

Миллион векторов размерности 384 в FP32 занимают:

\[
10^6\times384\times4=1\,536\,000\,000\text{ байт}\approx1.43\text{ GiB}.
\]

Это только сырая матрица. Индекс, граф соседей, ID, текст, метаданные и служебные структуры увеличат объём.

При обновлении chunk нужно пересчитать его вектор и обновить запись. При замене модели нужно создать новый согласованный индекс. Для воспроизводимости фиксируйте:

- model ID и revision;
- tokenizer, pooling, нормировку и префиксы;
- правила chunking и включения заголовков;
- метрику расстояния и параметры индекса;
- версии библиотек и корпус.

Размерность, записанная в схеме коллекции, защищает только от несовпадения числа координат. Она не обнаружит смешение двух разных моделей одинаковой размерности.

## 11. Практикум

1. Запустите exact search через NumPy на E5-векторах общего корпуса.
2. Сравните поиск точных `E17` и `E71` с BM25.
3. Проверьте русский вопрос к английскому и немецкому документам.
4. Замените E5 на multilingual MiniLM, уберите E5-префиксы и переиндексируйте весь корпус. Учтите её меньший лимит длины.
5. Перенесите поиск в Qdrant local mode и проверьте соответствие результатов точному поиску.
6. Для большого корпуса отдельно измерьте ANN Recall@k, человеческий retrieval Recall@k и задержку.

**Критерий понимания:** студент объясняет, почему неверный embedding нельзя исправить идеальным ANN-индексом и почему ближайший документ может не содержать ответа.
