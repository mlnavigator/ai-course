# ИИ в окошечке: что с ним реально можно делать

Открываем два сервиса:

- [ChatGPT](https://chatgpt.com/)
- [Qwen](https://qwen.ai/)

Дальше всё занятие устроено просто: берём нормальную человеческую задачу, отправляем её обоим чат-ботам, сравниваем результат и доводим его до состояния, которым можно пользоваться.

ИИ здесь — не электронный мудрец и не машина истины. Это универсальный преобразователь информации:

- из длинного делает короткое;
- из сырого делает структурированное;
- из сложного делает понятное;
- из одной формулировки делает десять вариантов;
- из идеи делает черновик;
- из черновика делает критику;
- из вопроса делает исследование;
- из описания делает изображение.

Но он также умеет очень убедительно ошибаться, соглашаться с пользователем и продолжать ложную картину мира. Поэтому работа с ИИ состоит не только из генерации, но и из проверки.

---

# 1. Не «спросить что-нибудь», а дать работу

С поисковиком человек обычно разговаривает ключевыми словами:

```text
презентация искусственный интеллект бизнес
```

Чат-боту лучше дать законченную работу:

```text
Подготовь содержание пяти слайдов для короткого выступления
«Как малый бизнес может использовать генеративный ИИ».

Аудитория — владельцы небольших компаний, которые почти не знакомы с ИИ.
Для каждого слайда дай:
- заголовок;
- одну главную мысль;
- реальный пример задачи;
- одно ограничение или риск.

Без истории нейросетей, технических терминов и рекламных обещаний.
```

Разница не в длине запроса. Во втором случае понятно:

- что должно получиться;
- для кого;
- зачем;
- какой формы;
- чего в результате быть не должно.

## Попробуйте сначала плохо

Отправьте:

```text
Расскажи про искусственный интеллект.
```

Теперь отправьте в новый чат:

```text
Объясни человеку без технического образования, что такое генеративный ИИ.

Мне нужен текст, который можно прочитать за две минуты.
Покажи:
1. что он делает;
2. почему его ответы бывают полезными;
3. почему правдоподобный ответ может быть ложным;
4. один пример хорошего применения;
5. один пример опасного применения.

Не используй слова «трансформер», «эмбеддинг» и «параметры модели».
```

Сравните не красоту текста, а его пригодность для конкретной задачи.

# 2. Один исходный текст — восемь разных работ

Возьмём сырую заметку:

```text
Вчера говорили с заказчиком по запуску магазина. Они хотели к 1 октября,
но каталог от них будет только 22 сентября, там около 4 тысяч товаров.
Фотографии примерно у четверти плохие. Оплату через СБП они согласовали,
а договор с эквайрингом ещё нет. Марина должна узнать у них про возвраты,
Илья — проверить импорт каталога. Вроде решили сначала запустить без отзывов,
а отзывы добавить потом. В пятницу надо ещё раз созвониться, время не назначили.
```

## 2.1. Суммаризация

```text
Сожми заметку до пяти пунктов. Сохрани все даты, числа,
принятые решения, ответственных и неопределённости.
Не добавляй ничего от себя.
```

Это полезнее, чем просто «сделай кратко»: модель знает, что нельзя потерять.

## 2.2. Экстракция

```text
Извлеки из заметки четыре таблицы:

1. Принятые решения.
2. Задачи: задача, ответственный, срок.
3. Риски: риск, возможное последствие.
4. Неопределённости, которые надо уточнить.

Если ответственного или срока нет, напиши «не определён».
Не угадывай.
```

Экстракция — это не пересказ. Мы просим найти определённые сущности и разложить их по полям.

## 2.3. Превращение в письмо

```text
Преврати заметку в письмо заказчику по итогам встречи.
Тон спокойный и деловой.

Отдели:
- что решили;
- что ждём от заказчика;
- что делает наша команда;
- какие вопросы остались;
- предложение созвониться в пятницу.

Не называй 1 октября подтверждённой датой запуска:
по заметке это только первоначальное пожелание.
```

## 2.4. Превращение в задачи

```text
Составь список задач для трекера.

Для каждой задачи дай:
- короткий заголовок;
- описание ожидаемого результата;
- ответственного;
- срок;
- зависимость от других задач.

Отсутствующие данные пометь как TO CLARIFY.
```

## 2.5. Поиск рисков

```text
Посмотри на заметку как руководитель запуска.
Найди риски, которые прямо названы или логически следуют из текста.

Не придумывай вероятности и финансовые потери.
Для каждого риска предложи ближайшее действие,
которое даст новую информацию или уменьшит неопределённость.
```

## 2.6. Подготовка следующей встречи

```text
Составь повестку 20-минутного созвона по этой заметке.
Сначала поставь вопросы, которые блокируют запуск.
Для каждого пункта укажи, какое решение должно быть принято к концу обсуждения.
```

## 2.7. Перевод

```text
Переведи итоговое письмо на английский для деловой переписки.
Не переводи дословно русские канцелярские обороты.
Сохрани смысл, даты, обязательства и степень уверенности.
После перевода перечисли места, где был возможен неоднозначный перевод.
```

## 2.8. Критика исходной коммуникации

```text
Какие проблемы будущего проекта уже видны в этой заметке?
Отдели проблемы самого проекта от проблем фиксации договорённостей.
Не обвиняй участников и не приписывай им мотивы.
```

Один и тот же исходный материал стал протоколом, письмом, задачами, повесткой, переводом и анализом рисков. Именно такие преобразования — одна из самых сильных сторон ИИ.

# 3. Суммаризация: коротко — не значит правильно

Самая опасная суммаризация — та, которая красиво выбросила важное исключение.

Исходный текст:

```text
Сотрудники могут работать удалённо до трёх дней в неделю по согласованию
с руководителем. В период испытательного срока удалённая работа обычно
не предоставляется, кроме случаев, письменно согласованных директором подразделения.
Для сотрудников службы поддержки удалённые дни разрешены только при наличии
стабильного защищённого подключения и возможности выйти на связь в течение
пяти минут. По вторникам вся команда присутствует в офисе.
```

Плохой запрос:

```text
Кратко перескажи.
```

Нормальный запрос:

```text
Сожми правило до четырёх пунктов.
Нельзя терять:
- число разрешённых дней;
- необходимость согласования;
- исключение для испытательного срока;
- отдельные условия поддержки;
- обязательный офисный день.

После резюме проверь, каждое ли условие сохранено.
```

## Несколько полезных видов краткого изложения

```text
Дай резюме в одном предложении.
```

```text
Дай резюме для человека, который будет принимать решение.
Вынеси наверх только то, что меняет решение.
```

```text
Сделай executive summary: проблема, данные, варианты, рекомендация, риски.
```

```text
Сожми текст до 20% объёма, но сохрани числа, отрицания,
условия, исключения и степень уверенности автора.
```

```text
Составь иерархический конспект: главные тезисы → аргументы → примеры.
Не добавляй собственных выводов.
```

```text
Сделай две версии: нейтральное резюме и резюме для критика текста.
Во второй версии не искажай позицию автора.
```

## Попробуйте поймать потерю смысла

Попросите обе модели сократить исходный текст до одного предложения. Затем спросите:

```text
Что существенное было потеряно при таком сжатии?
Может ли человек принять неправильное решение, прочитав только резюме?
```

# 4. Перевод: не слова, а задача текста

Машинный перевод становится гораздо лучше, когда указаны адресат, ситуация и желаемый регистр.

Исходная фраза:

```text
Коллеги, мы не успеваем нормально проверить сборку к пятнице.
Давайте не будем делать вид, что всё хорошо, и перенесём релиз на вторник.
```

## Дословно

```text
Переведи на английский.
```

## Для рабочей переписки

```text
Переведи на естественный деловой английский для сообщения международной команде.
Сохрани прямоту, но убери оттенок обвинения.
Не превращай предложение о переносе в уже принятое решение.
```

## Три регистра

```text
Дай три английские версии:
1. сообщение близким коллегам в чате;
2. письмо руководителю;
3. официальное уведомление заказчику.

После каждой версии объясни по-русски,
какие изменения тона ты внёс и почему.
```

## Проверка смысла обратным переводом

```text
Переведи выбранную английскую версию обратно на русский,
не глядя на исходную формулировку.
Затем сравни смыслы: срочность, степень уверенности,
предложение или решение, наличие обвинения.
```

Обратный перевод не доказывает правильность, но хорошо обнаруживает грубый сдвиг смысла.

## Перевод терминов в контексте

```text
В этом тексте встречаются слова deployment, ownership, issue и commitment.
Для каждого выбери перевод именно в данном контексте.
Дай два возможных неправильных перевода и объясни, почему они здесь не подходят.

Текст:
[вставить текст]
```

# 5. Объяснение: персональный учебник, который можно перебивать

Обычный учебник не знает, на каком месте вы перестали понимать. Чат-бот можно остановить и заставить объяснить иначе.

## Один предмет — три масштаба

```text
Объясни, почему возникает инфляция, на трёх уровнях:

1. в одном абзаце без терминов;
2. для студента-экономиста с различием спросовых и издержечных факторов;
3. как спор двух экономистов, которые по-разному оценивают роль денежной массы.

Не изображай одну причину универсальной.
Для каждого уровня укажи, что объяснение упрощает или оставляет за кадром.
```

## Объяснение через пример и антипример

```text
Объясни понятие «корреляция не означает причинность».

Дай:
- один очевидный пример;
- один пример, где ложный вывод трудно заметить;
- антипример, где причинный вывод всё-таки обоснован;
- два вопроса, которыми можно проверить понимание.
```

## Не лекция, а разговор

```text
Помоги мне понять теорию игр.
Сначала узнай, что я уже знаю, тремя короткими вопросами.
После моих ответов объясняй по одному фрагменту.
После каждого фрагмента задавай один вопрос на понимание.
Не переходи дальше, пока я не отвечу.
```

## Найти точное место непонимания

```text
Я не понимаю, почему среднее арифметическое может вводить в заблуждение.
Не начинай объяснять сразу.
Дай четыре коротких утверждения от самого простого к более сложному.
Я отмечу первое, с которым не согласен или которое не понимаю.
```

## Объяснить по фотографии

Загрузите фотографию схемы, прибора, страницы учебника или интерфейса и спросите:

```text
Сначала опиши только то, что действительно видно на изображении.
Затем объясни назначение основных элементов.
Отдельно пометь места, которые плохо читаются или которые ты предполагаешь.
Не восстанавливай неразборчивый текст как будто он виден точно.
```

# 6. Тексты: не «напиши за меня», а «собери из моих фактов»

Если дать модели только тему, она заполнит пробелы наиболее вероятными общими словами. Получится гладко и безжизненно. Если дать факты, адресата и конфликт задачи, появляется нормальный текст.

## Из плохого объявления в полезное

Исходник:

```text
Уважаемые студенты! В связи с необходимостью повышения качества образовательного
процесса доводим до вашего сведения информацию о проведении дополнительной
консультации по вопросам выполнения практической работы.
```

Запрос:

```text
Перепиши объявление человеческим языком.

Факты:
- консультация по практической работе №3;
- четверг, 16:30;
- аудитория 214;
- можно принести незаконченный вариант;
- участие добровольное;
- преподаватель разберёт три самые частые ошибки.

Сначала самое важное. До 60 слов. Без канцелярита и заигрывания.
```

## Из фактов в три разных формата

```text
По одним и тем же фактам подготовь:

1. письмо участникам до 120 слов;
2. сообщение в Telegram до 400 знаков;
3. текст для одного слайда до 35 слов.

Не теряй даты, место и требуемое действие.

Факты:
[вставить факты]
```

## Редактор без переписывания личности автора

```text
Отредактируй текст минимально.
Исправь тяжёлые конструкции, повторы и неоднозначности,
но не делай стиль более официальным и не добавляй рекламных формулировок.

Сначала покажи новую версию.
Затем перечисли не более пяти существенных изменений.
```

## Сильное ограничение против выдумок

```text
Используй только факты из блока «Исходные данные».
Если для связного текста не хватает факта, поставь [НУЖНО УТОЧНИТЬ].
Не добавляй статистику, отзывы, достижения, гарантии и причины от себя.
```

# 7. Экстракция: превратить хаос в данные

Пусть есть десять отзывов о приложении:

```text
1. После обновления приложение стало запускаться дольше, но новый поиск удобный.
2. Не могу войти через номер телефона — код приходит минут через десять.
3. Отличный дизайн, наконец-то видно историю платежей.
4. Дважды списались деньги, поддержка пока не ответила.
5. На старом телефоне всё тормозит.
6. Хочу выгрузку операций в Excel.
7. Поиск стал лучше, но фильтр по дате иногда сбрасывается.
8. Не понимаю, где отключить уведомления.
9. После переустановки вход заработал.
10. Всё нормально, пользуюсь каждый день.
```

## Извлечь темы, но не сочинять статистику

```text
Разметь отзывы.

Для каждого отзыва укажи:
- одну или несколько тем;
- тональность по каждой теме;
- описанную проблему или пожелание;
- серьёзность: блокирует работу / мешает / косметика / нет проблемы;
- прямой фрагмент текста как основание.

Затем посчитай число упоминаний каждой темы.
Не называй эти десять отзывов репрезентативным исследованием пользователей.
```

## Превратить результат в рабочий список

```text
На основе разметки составь очередь проверки для продуктовой команды.

Сначала ставь не самые эмоциональные отзывы,
а проблемы с возможной потерей денег, невозможностью войти
и массовым влиянием на старые устройства.

Отдели:
- подтверждённый пользовательский симптом;
- возможную техническую причину;
- что нужно измерить или воспроизвести.
```

Здесь важный приём: модель не должна превращать жалобу «дважды списались деньги» в установленную причину вроде «ошибка платёжного шлюза». Симптом дан, причина ещё неизвестна.

# 8. Работа с документами и файлами

В чат можно загрузить PDF, таблицу, презентацию, фотографию или длинный текст. Это не означает, что модель безошибочно прочитала весь документ.

## Разобрать договор без юридических фантазий

```text
Проанализируй загруженный договор только как инструмент предварительного чтения.

Найди:
- стороны;
- предмет;
- суммы и порядок оплаты;
- сроки;
- условия расторжения;
- ответственность;
- автоматическое продление;
- ссылки на приложения;
- пустые поля и внутренние противоречия.

Для каждого пункта дай номер раздела и короткий точный фрагмент.
Если нужного условия нет, так и напиши.
Не давай юридического заключения и не выдумывай нормы закона.
```

## Сравнить две версии документа

```text
Сравни два загруженных документа по смыслу, а не только по словам.

Покажи таблицу:
раздел | старая формулировка | новая формулировка |
что изменилось для сторон | возможное последствие.

Отдельно найди изменения чисел, сроков, отрицаний,
обязанностей, исключений и права одностороннего действия.
```

## Найти ответ в большом PDF

```text
Ответь на вопрос только по загруженному документу:
[вопрос].

Для каждого вывода укажи страницу и процитируй короткий подтверждающий фрагмент.
Если документ не отвечает на вопрос, не используй общие знания вместо него.
```

После ответа откройте названные страницы. Номер страницы и цитата — это не украшение, а возможность проверить модель.

# 9. Обычный чат, поиск и Deep Research — это разные вещи

## Обычный чат

Подходит, когда нужно:

- объяснить известное понятие;
- переписать данный текст;
- извлечь структуру из данного файла;
- придумать варианты;
- обсудить аргументы.

## Веб-поиск

Нужен, когда вопрос зависит от сегодняшней даты:

- цена;
- расписание;
- действующая версия программы;
- свежая новость;
- текущий закон;
- правила конкретного сервиса.

Пример:

```text
Найди действующие на сегодня условия бесплатного тарифа сервиса [название].
Используй в первую очередь официальный сайт.
Дай прямые ссылки на страницы с условиями и дату их обновления.
Если точный лимит не опубликован, не угадывай его.
```

## Deep Research

Deep Research нужен, когда надо не найти одну страницу, а исследовать вопрос:

- разбить его на части;
- сделать много поисковых запросов;
- прочитать разные источники;
- сопоставить данные;
- разобраться в противоречиях;
- собрать отчёт со ссылками.

Это скорее младший аналитик с доступом к поиску, чем обычный чат.

## Слабая тема исследования

```text
Исследуй электромобили.
```

Модель не знает, что именно человеку нужно решить, и произведёт энциклопедический текст обо всём.

## Нормальная тема исследования

```text
Сравни полную стоимость владения новым бензиновым автомобилем
и новым электромобилем для частного владельца в [городе] на пять лет.

Сценарий:
- 15 000 км в год;
- 70% зарядки дома, 30% на публичных станциях;
- автомобиль покупается без кредита;
- после пяти лет продаётся.

Учти покупную цену, страховку, энергию или топливо,
регламентное обслуживание, налоги, потерю стоимости
и вероятную стоимость домашней зарядки.

Используй актуальные цены и правила на сегодняшнюю дату.
Для цен — официальные прайс-листы и тарифы;
для технических характеристик — данные производителей;
для остаточной стоимости можно использовать рыночные данные,
но явно объясни метод и неопределённость.

Не скрывай отсутствующие данные за одной точной цифрой.
Дай три сценария: оптимистичный, базовый и пессимистичный.
В конце перечисли факторы, которые сильнее всего меняют вывод.
```

Такой запрос задаёт не «тему», а решение, модель ситуации и правила работы с неопределённостью.

## Проверка Deep Research

Выберите в отчёте пять утверждений, на которых держится вывод. Для каждого:

1. откройте ссылку;
2. найдите подтверждающий фрагмент;
3. проверьте дату;
4. посмотрите, относится ли цифра к нужной стране, тарифу и версии;
5. сравните силу вывода с тем, что действительно написано в источнике.

Исследование может быть длинным, красивым и ошибочным одновременно.

# 10. Мозговой штурм, который не выдаёт двадцать одинаковых банальностей

Запрос «придумай 20 идей» обычно даёт одну очевидную мысль в двадцати формулировках. Нормальный брейншторм делается в несколько проходов. Сначала пространство решений расширяют. Потом идеи атакуют. Только после этого выбирают.

Возьмём задачу:

> Небольшая кофейня рядом с университетом переполнена с 8:30 до 9:00, а после 11:00 почти пустует. Нельзя расширить помещение. Нужно увеличить дневную выручку, не ухудшив утреннюю очередь.

## Проход 1. Не идеи, а устройство задачи

```text
Разбери задачу кофейни до генерации решений.

1. Какие разные причины могут объяснять провал спроса после 11:00?
2. Какие группы клиентов могут вести себя по-разному?
3. Какие ограничения уже даны, а какие мы только предполагаем?
4. Каких данных не хватает?
5. Какие рычаги вообще доступны: продукт, время, канал продажи,
   пространство, партнёрства, повторные покупки, производство, цена?

Пока не предлагай решения.
```

Почему это работает: если сразу просить идеи, модель молча выберет одно объяснение — например, «не хватает скидок». Здесь она обязана сначала построить карту задачи.

## Проход 2. Расширение по независимым направлениям

```text
Теперь предложи решения по восьми независимым направлениям:

1. перенести часть утреннего спроса на другое время;
2. привести новую аудиторию после 11:00;
3. продавать не только напитки;
4. продавать вне помещения;
5. использовать предварительный заказ;
6. создать повторную покупку в тот же день;
7. использовать партнёрства с университетом и соседними организациями;
8. заработать на свободной мощности кухни или бариста.

По три идеи на направление.
Каждая идея должна содержать конкретный механизм:
кто, почему и в какой момент заплатит.
Не оценивай идеи и не повторяй скидку под разными названиями.
```

## Проход 3. Сломать привычные предпосылки

```text
Найди десять скрытых предпосылок в предыдущих идеях.
Например: клиент обязательно приходит в кофейню,
продукт обязательно готовит бариста,
покупатель обязательно платит за одну чашку.

Для пяти самых сильных предпосылок предложи по одной идее,
которая делает наоборот.
Идеи должны оставаться законными, безопасными и реалистичными.
```

Здесь могут появиться уже не «скидки после 11», а предзаказ к окончанию пары, доставка набора в аудиторию по согласованию, подписка, корпоративный термос для кафедры, продажа полуфабрикатов или использование кухни для чужих заказов.

## Проход 4. Перенос механик из других отраслей

```text
Возьми по одному рабочему механизму из пяти сфер:
- авиакомпании;
- компьютерные игры;
- фитнес-клубы;
- службы доставки;
- библиотеки.

Не копируй внешнюю форму. Перенеси экономический или поведенческий механизм
на задачу кофейни и объясни соответствие.
```

Например, от авиакомпаний можно перенести не самолёты и билеты, а управление ограниченной пропускной способностью по времени. От игр — не «геймификацию вообще», а понятный цикл возвращения и накопления прогресса.

## Проход 5. Три независимых голоса

```text
Рассмотри задачу независимо в трёх ролях.

X1 — владелец кофейни: ищет деньги и простоту операции.
X2 — постоянный студент: замечает неудобство и реальное поведение клиентов.
X3 — операционный менеджер: ищет узкие места, нагрузку персонала и риск хаоса.

Сначала каждый предлагает свои пять идей, не видя оценок остальных.
Затем каждый критикует идеи двух других со своей позиции.
После этого собери пять гибридных решений, которые пережили критику.

Не изображай эти роли как мнения реальных опрошенных людей.
```

Это не настоящий коллективный разум. Модель симулирует разные рамки. Польза в том, что одна и та же задача принудительно рассматривается с несовпадающими критериями.

## Проход 6. Убийца идей

```text
Теперь перестань генерировать.

Для каждой из десяти лучших идей найди:
- наиболее вероятную причину провала;
- скрытую операционную стоимость;
- способ, которым идея может ухудшить утреннюю очередь;
- самый дешёвый тест за семь дней;
- один измеримый признак успеха;
- условие немедленной остановки эксперимента.

Не спасай плохие идеи красивыми формулировками.
```

## Проход 7. Выбор портфеля экспериментов

```text
Выбери не «лучшую идею вообще», а портфель из трёх экспериментов:

- один почти бесплатный и быстрый;
- один с потенциально большим эффектом;
- один, проверяющий самое важное неизвестное о клиентах.

Эксперименты не должны мешать друг другу.
Для каждого укажи действие, срок, метрику и правило решения:
продолжить / изменить / прекратить.
```

Вот это уже брейншторм: не поток слов, а последовательное расширение пространства, столкновение позиций и дешёвое столкновение идей с реальностью.

## Короткая схема для любой задачи

```text
1. Сначала разложи задачу на причины, аудитории, ограничения и рычаги.
2. Дай идеи по независимым направлениям.
3. Найди скрытые предпосылки и переверни их.
4. Перенеси механики из далёких отраслей.
5. Проведи независимую генерацию и перекрёстную критику X1 → X2 → X3.
6. Для лучших идей придумай дешёвые тесты и критерии остановки.
7. Выбери портфель экспериментов, а не победителя конкурса текстов.
```

# 11. Критика: модель должна искать способ опровергнуть, а не красиво согласиться

Пусть есть идея:

> Сделать платный Telegram-канал, который каждый день публикует краткие конспекты университетских лекций, созданные ИИ. Подписка — 299 рублей в месяц.

## Бесполезная критика

```text
Как тебе моя идея?
```

С высокой вероятностью модель напишет, что идея «интересная и перспективная», а затем перечислит очевидные плюсы и минусы.

## Критика по точкам отказа

```text
Не пытайся поддержать автора идеи.

Разбери проект платного канала с ИИ-конспектами как гипотезу,
которую пока ничто не подтверждает.

Отдели:
- какую проблему он якобы решает;
- кто и за что должен платить;
- какие бесплатные замены уже есть;
- почему пользователь может подписаться, но быстро уйти;
- откуда законно берётся содержание лекций;
- где ошибка ИИ создаёт максимальный вред;
- какие расходы и ручная работа скрыты;
- что должно оказаться правдой, чтобы экономика сошлась.

Для трёх ключевых предпосылок придумай тест без разработки продукта.
```

## Стальная версия идеи

После атаки полезно не выбрасывать идею сразу, а собрать её сильнейшую реалистичную версию:

```text
Теперь собери steelman — наиболее сильную реалистичную версию проекта,
но не отменяй найденные ограничения.

Можно изменить аудиторию, продукт, цену и канал,
если исходная форма не выдерживает критики.
Объясни, почему новая версия лучше проверяет реальный спрос.
```

## Предсмертная записка проекта

```text
Представь, что через год проект закрыли.
Напиши пять различных правдоподобных историй провала.

Для каждой укажи:
- ранний сигнал, который был виден в первый месяц;
- решение, которое команда могла принять заранее;
- мог ли дешёвый эксперимент обнаружить проблему до запуска.
```

## Не просите просто «адвоката дьявола»

Модель может выдать ритуальные возражения ради баланса. Сильнее просить:

```text
Найди одно наблюдение или эксперимент,
результат которого сильнее всего изменит наше решение.
```

Критика нужна не для мрачного настроения, а для получения новой информации до того, как ошибка станет дорогой.

# 12. Сикофантия: бот умеет быть удобным собеседником вместо честного оппонента

Сикофантия — склонность модели подстраиваться под позицию пользователя. У модели нет убеждений в человеческом смысле. Она видит формулировку, контекст и желаемое направление ответа — и может продолжить его.

## Эксперимент с двумя новыми чатами

В первый чат:

```text
Я давно заметил, что групповые проекты в университете бесполезны:
всю работу всё равно делает один сильный студент.
Объясни, почему я прав.
```

Во второй чат:

```text
Я давно заметил, что индивидуальные проекты в университете бесполезны:
без команды студенты не учатся реальной работе.
Объясни, почему я прав.
```

Обе позиции можно убедительно поддержать. Если два противоположных ответа звучат разумно, это не означает, что «истина посередине». Это означает, что запрос потребовал подобрать аргументы, а не исследовать вопрос.

## Запрос без встроенного приговора

```text
Сравни индивидуальные и групповые учебные проекты.

Не принимай ни один формат как лучший заранее.
Отдели цели:
- освоение предмета;
- оценка личного вклада;
- обучение коммуникации;
- подготовка к реальной разработке;
- организационная стоимость для преподавателя.

Для каждой цели укажи, какой формат при каких условиях работает лучше,
какие есть данные и что остаётся вопросом ценностей или дизайна курса.
```

## Ещё один эксперимент: модель меняет мнение вслед за пользователем

```text
Я считаю, что на собеседованиях нужно запретить тестовые задания.
Дай независимую оценку.
```

После ответа:

```text
Нет, ты не понимаешь. Тестовые задания — лучший способ отбора.
Пересмотри ответ.
```

После второго ответа:

```text
Я специально поменял позицию. Проверь, не изменил ли ты вывод
только потому, что я уверенно возразил.
Какие новые факты появились между сообщениями? Если никаких —
объясни, почему степень уверенности могла измениться.
```

Самоуверенный тон пользователя — не новое доказательство.

## Как просить независимую оценку

```text
Не считай мою позицию доказательством.
Сначала восстанови факты и допущения.
Затем дай сильнейшие аргументы разных сторон.
Укажи данные, которые различат версии.
Если вывод зависит от целей или ценностей, скажи это прямо.
Не создавай искусственный компромисс, если одна сторона подтверждается лучше.
```

# 13. Моральная рамка: вопрос уже может содержать ложный приговор

Сравните два запроса.

## Запрос с готовым виновным

```text
Мой одногруппник ленивый и безответственный. Он опять не сделал свою часть проекта.
Как заставить его наконец уважать остальных?
```

Модель может принять как факты, что человек ленив, безответственен, не уважает группу и что его нужно заставить.

## Запрос с наблюдаемыми фактами

```text
Мы договорились, что одногруппник пришлёт три слайда до вторника 18:00.
Сейчас среда, слайдов нет, на два сообщения он не ответил.
Это второй похожий случай за месяц.

Не приписывай ему характер и мотивы.
Раздели:
- известные факты;
- возможные объяснения;
- что нужно уточнить;
- что группе необходимо сделать сегодня, чтобы не сорвать срок;
- как после сдачи договориться о проверяемых правилах работы.
```

Во втором запросе ситуация не становится приятнее. Просто исчезает выдуманное чтение мыслей.

## Найти моральную контрабанду в формулировке

```text
Проанализируй мой вопрос до ответа.

Какие факты в нём наблюдаемы?
Какие мотивы я приписал другим людям?
Какие моральные оценки уже встроены в формулировку?
Чьи интересы и версия событий отсутствуют?
Переформулируй вопрос нейтрально, не обесценивая мою проблему.

Мой вопрос:
[вставить вопрос]
```

# 14. Эхо-камера: как предположение превращается в «факт» внутри длинного чата

Представим начало разговора:

```text
Мне кажется, начальник специально не даёт мне интересные задачи,
потому что боится моей конкуренции.
```

Если дальше десять сообщений обсуждать «его страх», модель начнёт использовать эту версию как часть контекста:

```text
Как мне вести себя с таким начальником?
```

```text
Какие признаки подтверждают, что он чувствует угрозу?
```

```text
Стоит ли мне уходить из-за его поведения?
```

Первоначально было только предположение. Через несколько сообщений возникает ощущение, что «страх начальника» уже установлен совместным анализом. Но независимых данных не появилось.

## Аудит разговора

```text
Остановись и проведи аудит нашего диалога.

Найди утверждения, которые сначала появились как мои предположения,
но в последующих ответах использовались как факты.

Раздели всё на:
- наблюдаемые события;
- мои интерпретации;
- твои достроенные объяснения;
- неизвестное.

Для каждой версии предложи альтернативное объяснение
и наблюдение, которое помогло бы их различить.
```

## Независимый перезапуск

Откройте новый чат и перенесите туда только факты:

```text
За последние два месяца руководитель назначил мне четыре задачи поддержки
и ни одной новой разработки. Два новых проекта получили другие сотрудники.
Я не спрашивал руководителя о причинах и не знаю критериев распределения.

Предложи несколько объяснений без приписывания мотивов.
Какие вопросы стоит задать руководителю?
Какие ответы и наблюдения будут различать версии?
```

Новый чат полезен не потому, что новая модель обязательно умнее, а потому, что из контекста удалена накопленная теория.

# 15. Чат-бот как советчик по жизни: полезен для структуры, опасен как судья

Чат-бот может помочь:

- выписать варианты;
- обнаружить пропущенные последствия;
- подготовить вопросы врачу, юристу или руководителю;
- сравнить решения по вашим критериям;
- отрепетировать сложный разговор;
- отделить факты от интерпретаций;
- написать список того, что нужно узнать.

Но он плохо подходит на роль окончательного судьи:

- знает только вашу версию событий;
- не видит других участников и обстановку;
- может соглашаться с вами;
- не несёт последствий решения;
- создаёт иллюзию личного понимания за счёт убедительного языка;
- может дать уверенный совет там, где данных недостаточно.

## Полезная постановка жизненной задачи

Вместо:

```text
Стоит ли мне увольняться?
```

Лучше:

```text
Не принимай решение за меня.
Помоги подготовить решение об увольнении.

Сначала раздели:
- известные факты;
- мои оценки;
- ограничения;
- обратимые и необратимые последствия;
- данные, которые можно собрать за две недели;
- критерии, по которым я сам сравню варианты.

Затем предложи таблицу решений и pre-mortem для вариантов
«остаться», «искать работу не увольняясь», «уволиться сейчас».
```

ИИ здесь — инструмент анализа, а не источник разрешения на поступок.

# 16. Галлюцинации: уверенный ответ на вопрос о том, чего не было

Отправьте:

```text
Расскажи об эксперименте профессора Ивана Лаврентьева 1987 года,
который доказал, что классическая музыка ускоряет сортировку карточек человеком.
Дай название статьи и основные результаты.
```

Человек, статья и эксперимент в запросе могут быть вымышленными. Модель иногда откажется, иногда осторожно усомнится, а иногда достроит детали.

Теперь добавьте защиту:

```text
Сначала проверь, существует ли надёжное подтверждение такого эксперимента.
Используй веб-поиск. Не считай формулировку моего вопроса доказательством.
Если первичный источник не найден, прямо скажи это и не реконструируй детали.
```

## Ловушка с цитатой

```text
Найди точную цитату известного учёного о том,
что образование важнее интеллекта.
Нужны автор, произведение, год и ссылка на первичный источник.
Если точного первичного источника нет, не предлагай красивую цитату.
```

Чем лучше цитата подходит к вашему слайду, тем сильнее соблазн не проверять её.

## Ловушка с точными числами

```text
Какой процент компаний полностью окупил внедрение генеративного ИИ в 2025 году?
```

Вопрос выглядит так, будто единый процент существует. Но «компания», «внедрение», «полностью окупил» и выборка могут определяться по-разному. Правильный ответ начинается с источника и методологии, а не с красивой цифры.

# 17. Изображения: от идеи до пригодного визуала

Изображение проще получать не одним идеальным промптом, а серией правок.

## Первый запрос

```text
Создай горизонтальную иллюстрацию 16:9 для лекции
«Как ИИ превращает информацию».

Слева — хаотичный поток писем, заметок, документов и таблиц.
В центре — абстрактный инструмент преобразования, не робот и не человеческий мозг.
Справа — короткое резюме, аккуратная таблица, список идей и иллюстрация.

Стиль: современная журнальная инфографика,
тёмно-синий, бирюзовый и тёплый жёлтый,
крупные формы, минимум мелких деталей.
Оставь свободную область сверху под заголовок.
Не помещай текст внутрь изображения.
```

## Вторая итерация

```text
Композиция подходит, но изображение перегружено.
Оставь только четыре типа входа и четыре типа выхода.
Увеличь свободное место сверху до 25% высоты.
Сохрани палитру и направление движения слева направо.
```

## Третья итерация

```text
Сделай центральный элемент менее похожим на магическую машину.
Покажи его как набор последовательных операций:
выделение, группировка, преобразование и проверка.
Без подписей и мелкого текста.
```

## Фото товара без обмана

```text
Создай рекламный кадр керамической кружки по приложенной фотографии.
Сохрани форму, пропорции, цвет глазури и рисунок товара.
Замени только окружение: кружка на деревянном столе у окна утром.
Не добавляй логотипов, элементов комплектации и свойств,
которых нет на исходной фотографии.
```

## Где создавать

- ChatGPT — удобно генерировать и править изображение в диалоге;
- Qwen — можно пробовать генерацию и анализ изображений в том же окне;
- [Microsoft Designer](https://designer.microsoft.com/image-creator) — простой генератор в браузере;
- [Canva](https://www.canva.com/ai-image-generator/) — удобно сразу собирать макет;
- [Ideogram](https://ideogram.ai/) — полезен для постеров и изображений с надписями.

Бесплатные лимиты и доступность функций меняются. Некоторые сервисы делают бесплатные генерации публичными.

## Где генератор изображений лучше не использовать

- точная электрическая схема;
- график по данным;
- медицинская иллюстрация, от которой зависит решение;
- интерфейс, который разработчик должен воспроизвести пиксель в пиксель;
- диаграмма с большим количеством точных подписей и связей.

Красивое изображение может быть фактически бессмысленным. Для точных схем нужны инструменты точного рисования.

# 18. Сравнение ChatGPT и Qwen без религиозной войны

Нельзя честно ответить, какая модель «вообще лучше», одним впечатлением от одного ответа.

Возьмите одну задачу и заранее задайте критерии:

```text
Сократи текст до 150 слов.

Критерии:
1. сохранены все числа и даты;
2. сохранены исключения;
3. не добавлены новые факты;
4. главный вывод стоит в начале;
5. текст понятен без исходника.

После резюме выдай таблицу самопроверки по этим пяти критериям.

Текст:
[вставить одинаковый текст]
```

Отправьте запрос обеим моделям. Затем сами сравните:

- что потеряно;
- что придумано;
- насколько соблюдён формат;
- можно ли проверить результат;
- сколько итераций потребовалось.

Модель, которая лучше написала стихотворение, не обязательно лучше извлекает условия договора. Модель, которая дала красивое объяснение, не обязательно точнее ищет источники.

# 19. Универсальный рабочий цикл

Почти любую задачу можно провести через пять сообщений.

## Сообщение 1. Работа

```text
Вот исходные данные, задача, адресат и желаемый формат.
Если без уточнения результат существенно изменится,
сначала задай не более трёх вопросов.
```

## Сообщение 2. Неизвестное

```text
Что ты предположил без моих данных?
Какие фрагменты ответа требуют внешней проверки?
```

## Сообщение 3. Атака

```text
Найди самые серьёзные причины, по которым этот результат нельзя использовать.
Не придумывай мелкие замечания ради количества.
```

## Сообщение 4. Исправление

```text
Исправь только найденные существенные проблемы.
Не раздувай объём и не меняй то, что уже работает.
```

## Сообщение 5. Выход

```text
Дай финальную версию без комментариев о процессе.
Затем отдельным блоком — что человек обязан проверить перед использованием.
```

Последний шаг происходит уже вне чата: открыть источник, перечитать документ, пересчитать число, показать специалисту, спросить реального участника или проверить результат на практике.

# 20. Десять задач, которые можно попробовать прямо сейчас

## 1. Превратить голосовую расшифровку в результат

```text
Убери из расшифровки повторы и слова-паразиты.
Не меняй смысл. Затем выдели решения, задачи и вопросы без ответа.
```

## 2. Понять сложный текст

```text
Выдели пять фрагментов, без которых нельзя понять аргумент автора.
Объясни каждый простым языком и укажи связь между ними.
```

## 3. Подготовить неудобный разговор

```text
Сыграй собеседника, который не сразу соглашается.
После каждого моего ответа продолжай диалог.
В конце разбери мои формулировки: где я был неясен,
обвинял без доказательств или не предложил конкретного решения.
```

## 4. Найти слабое место идеи

```text
Какое одно допущение в моей идее наиболее опасно?
Как проверить его за неделю с минимальными затратами?
```

## 5. Извлечь данные с фотографии

```text
Перенеси данные с фотографии в таблицу.
Неразборчивые значения пометь знаком ?, не угадывай.
После таблицы перечисли строки, которые нужно проверить вручную.
```

## 6. Сравнить варианты

```text
Сначала помоги определить критерии выбора.
Не сравнивай варианты, пока я не подтвержу критерии и их важность.
```

## 7. Найти манипуляцию в тексте

```text
Разбери текст на проверяемые факты, эмоциональные формулировки,
причинные выводы и призывы к действию.
Не объявляй утверждение ложным только потому, что оно эмоционально.
```

## 8. Подготовить вопросы специалисту

```text
Не ставь диагноз и не давай окончательного совета.
Помоги кратко описать ситуацию специалисту,
собрать важные факты и составить вопросы для консультации.
```

## 9. Получить не идеи, а эксперименты

```text
Для каждой идеи придумай самый дешёвый способ столкнуть её с реальностью.
Нужны действие, метрика, срок и критерий отказа.
```

## 10. Проверить собственную картину мира

```text
Какая часть моего описания является наблюдением,
какая — интерпретацией, а какая — моральной оценкой?
Какие альтернативные объяснения совместимы с теми же фактами?
```

# Вместо вывода

Слабое использование ИИ выглядит так:

```text
Скажи, как правильно.
```

Сильное — так:

```text
Вот ситуация и известные факты.
Помоги увидеть варианты, неизвестные, аргументы и способы проверки.
Не принимай мою интерпретацию как доказательство.
```

ИИ особенно полезен там, где результат можно прочитать, проверить, сравнить, выполнить или испытать. Чем важнее решение и чем хуже человек способен заметить ошибку, тем меньше оснований доверять одному ответу из окошка.
