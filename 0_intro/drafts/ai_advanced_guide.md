# Работа с ИИ на практике: продвинутые сценарии

## Контекстное окно: почему ИИ «забывает» и как с этим жить

У ИИ есть лимит памяти. Когда диалог становится длинным, он начинает терять внимание к самому началу.

**Что это значит на практике:**

Ты начал с чёткого ТЗ в первом сообщении. Потом 15 раз его корректировал. К 16-му сообщению ИИ помнит последние три правки, но оригинальное ТЗ уже размыто.

**Правило №1: если диалог длиннее 20-30 сообщений — копируй результат в новый чат**

Не проси ИИ «вернуться к началу». Он помнит начало хуже, чем середину.

```
Копируй сюда свой текст:
[вставь результат]

Новая задача: [новая формулировка].
Не обращай внимание на предыдущий контекст — это новая задача.
```

**Правило №2: чем дальше диалог, тем короче и конкретнее должны быть запросы**

В начале чата ИИ помнит всё. К середине — только последние 10-15 сообщений. К концу — последние 3-5. Если задача сложная, не растягивай один диалог на час. Разбей на несколько коротких.

**Правило №3: «сброс» контекста**

Иногда ИИ слишком привязывается к старой формулировке и не может мыслить иначе. Помогает чистый старт.

```
Вот что я хочу сделать: [описание].
Но я хочу, чтобы ты забыл всё, что мы обсуждали ранее.
Это новая задача. Отвечай, не оглядываясь на прошлые сообщения.
```

**Практический пример:**

Представь, что ты пишешь аналитическую записку.

❌ **Неправильно:** один длинный диалог на 40 сообщений, где ты постоянно переформулируешь, просишь добавить, убирать, менять структуру.

✅ **Правильно:** 
- Чат 1: «сгенерируй черновик» (5 сообщений) → копируй черновик
- Чат 2: вставь черновик + «найди слабые места» (5 сообщений) → копируй критику
- Чат 3: вставь черновик + критику + «исправь по замечаниям» (5 сообщений) → финальный результат

Три коротких чата вместо одного длинного — качество выше.

## Конфиденциальность: что категорически нельзя пихать в публичный ИИ

Публичный ИИ — не приватное хранилище. Твои запросы могут сохраняться, использоваться для обучения модели, и в некоторых случаях — доступны модераторам или по запросу.

**Категорически нельзя отправлять:**

- Пароли, токены, ключи API
- Персональные данные людей (ФИО + паспортные данные, адреса, телефоны) — даже если это анонимизированные «данные клиентов»
- Внутренние документы компании, если они не предназначены для публичного использования
- Переписки, где есть реальные люди — даже без имён, по контексту можно понять, о ком речь
- Медицинские данные, финансовые документы, договоры с конфиденциальными условиями

**Что можно, но с осторожностью:**

- Черновики текстов — обычно безопасно
- Обобщённые данные без имён — если нет идентифицирующих деталей
- Учебные материалы, которые уже опубликованы

**Техника «анонимизации»:**

Если нужно показать ИИ документ с реальными данными, но без реальных данных:

```
Вот текст, из которого я убрал все имена, номера, суммы и адреса.
Оставил только структуру и логику. Посмотри, есть ли в ней логические ошибки?

[заменяешь «Иванов И.И.» на «первый участник», 
 суммы — на «X», даты — на «дата N»]
```

**Знак вопроса:** если ты сомневаешься, можно ли это отправлять — отправляй. Но не в публичный ИИ. В приватный или локальный инструмент. Лучше потерять 2 минуты на поиск альтернативы, чем получить утечку.

**Короткий чек-лист перед отправкой:**

- [ ] В тексте есть имена? Если да — замени на «лицо А», «лицо Б»
- [ ] Есть контакты? Если да — удали
- [ ] Есть суммы, даты, номера? Если да — замени на «X»
- [ ] Есть ссылки на внутренние системы? Если да — убери
- [ ] Это документ, который может навредить компании или людям при утечке? Если да — не отправляй

## Работа с несколькими источниками: склейка, сравнение, поиск противоречий

Самый мощный сценарий, который мало кто использует: загрузи два текста, попроси их сравнить.

**Склейка двух источников:**

```
Вот два текста:

Текст 1:
[вставь текст или загрузи файл]

Текст 2:
[вставь текст или загрузи файл]

Склей их в один coherent текст:
- Сохрани обе точки зрения
- Убери повторения
- Сделай плавные переходы между блоками
- Если они противоречат друг другу — отметь это
- Результат — единый текст, а не «текст 1 + текст 2»
```

**Сравнение двух версий одного текста:**

```
Вот две версии одного текста. Скажи мне:
— Что добавили во второй версии, чего не было в первой?
— Что убрали?
— Что изменилось по смыслу, а не только по форме?
- Есть ли во второй версии логические пробелы, которых не было в первой?
```

**Поиск противоречий между несколькими источниками:**

```
Вот три статьи на одну тему:

1. [ссылка или текст]
2. [ссылка или текст]
3. [ссылка или текст]

Скажи, где они расходятся. Что три утверждають одно, а четвёртый — другое?
Не старайся «сгладить» — покажи реальные противоречия.
```

**Конкретный пример — подготовка обзора:**

Ты пишешь обзор на тему. Нашёл 4 статьи. Вместо того чтобы читать их все и пытаться запомнить — загрузи в ИИ:

```
Вот 4 статьи на тему X. Сделай таблицу:

Столбец 1: автор/источник
Столбец 2: главный тезис
Столбец 3: какие данные приводят
Столбец 4: что упускают
Столбец 5: с кем согласен из остальных авторов

И в конце — одно предложение: какой из источников самый сильный и почему.
```

**Когда это особенно работает:**

- Подготовка обзора литературы (да, для учёбы)
- Сравнение двух кандидатов на позицию
- Подготовка к дебатам — найти все аргументы «за» и «против»
- Анализ конкурентов — загрузи описание двух конкурентов, получи сравнение

## Адаптация под платформы: один контент, разные форматы

У тебя есть материал — а он должен жить в пяти местах с пятью разными правилами.

**Базовый запрос:**

```
У меня есть вот этот текст:

[вставь текст]

Перепиши его в 4 варианта под разные платформы:

1. Пост для VK — до 300 слов, с эмодзи, с вовлекающим началом, 
   с вопросом в конце для комментариев
2. Тезисы для Telegram-канала — 3-5 булит-поинтов, 
   каждый — не длиннее 20 слов, без эмодзи
3. Письмо коллеге — краткое, по делу, без «воды»
4. Слайд-презентация — 5 слайдов, на каждом: заголоок + 3 булит-поинта

Сохрани общий смысл, но адаптируй формат и язык под каждую платформу.
```

**Пример «из жизни»:**

У тебя есть статья «Как правильно проводить мозговые штурмы» — 2000 слов.

- **Для VK:** «Топ-5 правил, которые превращают скучные совещания в генерацию идей 🔥» + эмодзи + вопрос «а вы согласны?»
- **Для Telegram:** 5 коротких тезисов. Каждый — отдельный булит-поинт. Без вступлений.
- **Для email коллеге:** «Посмотри, может, нам стоит внедрить это на наших еженедельных встречах» — 3 предложения + ссылка.
- **Для слайдов:** 5 слайдов. Каждый — одно правило. Минимум текста.

**И наоборот — из одного поста в длинный текст:**

```
Вот мой короткий пост для соцсети:

[пост]

Раскрой его в полноценную статью на 1500 слов.
Каждый тезис из поста — отдельная секция с примерами.
Добавь исследования, статистику, кейсы.
Сохрани живой тон.
```

**Правила адаптации по платформам:**

| Платформа | Длина | Тон | Что работает |
|---|---|---|---|
| VK | 200-500 слов | Неформальный | Вопросы, эмодзи, личный опыт |
| Telegram | 50-200 слов | Прямой, без воды | Булит-поинты, факты |
| Email | 100-300 слов | Деловой | Краткость, конкретика, призыв к действию |
| Презентация | 5-7 слайдов | Минимализм | Заголоок + 3 булит-поинта |
| Статья | 1000+ слов | Зависит от аудитории | Структура, примеры, источники |

## ИИ как редактор: не автор, а критик

Самая частая ошибка — просить ИИ «написать мне текст». Лучший результат, когда ИИ — редактор, а ты — автор.

**Редакторская критика текста:**

```
Вот мой текст. Оцени его как редактор с 15 годами опыта.

Не переписывай. Не улучшай. Просто скажи:
— Что работает хорошо (и почему)
- Что работает плохо (и почему)
- Где логический разрыв
- Где читатель заскучает
- Какой заголоок ты бы поставил вместо моего (если мой плохой)
- Один конкретный совет, который поднимет качество текста
```

**Редактура — пошагово:**

```
Шаг 1: Прочитай этот текст и скажи мне своё первое впечатление.
Не редактируй — просто скажи, что бросается в глаза.

[получил ответ]

Шаг 2: Теперь укажи 3 места, где текст weakest. Конкретно — номер абзаца, предложение, и что не так.

[получил ответ]

Шаг 3: А теперь укажи 3 места, где текст сильнее всего. Что работает и почему.

[получил ответ]

Шаг 4: Предложи три варианта заголовка — каждый в своём стиле.

[получил ответ]
```

**Проверка на «воду»:**

```
Этот текст содержит воду. Не просто убери лишние слова — 
оставь только то, без чего смысл ломается. 
Всё остальное — выкинь. Не жалей.
```

**Проверка на логику:**

```
Пройдись по этому тексту абзац за абзацем. 
Для каждого абзаца напиши: «главная мысль этого абзаца — ...».
Если главная мысль не совпадает с тем, что написано в абзаце, 
или если абзац не добавляет ничего нового — отметь это.
```

**Пример реальной редактуры:**

У тебя черновик эссе — 1500 слов.

1. Сначала просишь: «найди 5 мест, где можно сократить на 30%, не теряя смысла»
2. Потом: «убери все вводные слова (вообще, конечно, действительно, стоит отметить, что)»
3. Потом: «замени все «очень + прилагательное» на более точные слова»
4. Потом: «сделай переходы между абзацами плавнее»
5. Потом: «проверь, нет ли противоречий между абзацами»

Каждый шаг — отдельный запрос. Не всё сразу.

## Метакognition: как ИИ помогает понять, чего ты вообще хочешь

Самый недооценённый сценарий: ты заходишь в ИИ и НЕ ЗНАЕШЬ, что тебе нужно.

**Старт с неопределённости:**

```
Я хочу сделать что-то с темой [тема]. Не знаю что именно — 
то ли статью, то ли презентацию, то ли просто разобраться самому.

Помоги мне понять, что мне нужно на самом деле.
Задай мне 5 вопросов. Отвечай на них по одному — 
не задавай все сразу. Жди моих ответов.
```

**Почему это работает:**

Потому что ИИ задаёт вопросы, которые ты сам себе не задавал. И в процессе ответов ты сам приходишь к тому, что на самом деле хочешь.

**Пример:**

Ты: «Мне надо сделать что-то про нейросети для семинара»

ИИ: «Сколько времени у тебя есть?»
Ты: «Неделя»
ИИ: «Какой у тебя уровень подготовки по теме?»
Ты: «Средний»
ИИ: «Ты хочешь объяснить другим или разобраться самому?»
Ты: «Оба»
ИИ: «Тогда давай сделаем так: ты сделаешь мини-гид, 
в котором объясняешь нейросети как будто другому студенту. 
Это закроет обе потребности. Вот как это можно устроить...»

**«Разговор с незнакомцем»:**

```
Представь, что я — человек, который ничего не понимает в теме X.
Я сижу перед тобой и говорю: «я хочу разобраться, но не знаю с чего начать».

Задай мне серию вопросов, чтобы понять:
— Что я уже знаю?
- Чего мне не хватает?
- Какой результат мне нужен?

Не отвечай за меня. Не давай советов — пока только вопросы.
```

**«Найди, чего я не вижу»:**

```
Я думаю, что мне нужно [описание задачи]. Но я могу ошибаться.

Скажи: что я, скорее всего, упускаю из виду?
Какие альтернативы я не рассматриваю?
Есть ли более простой способ решить ту же проблему?
```

## Итеративная редактура: от чёрновика к золоту за 5 шагов

Методика для тех, кто пишет много и хочет, чтобы каждый текст был лучше предыдущего.

**Шаг 0: напиши максимально грязный черновик**

Не редактируй. Не переписывай. Не думай. Просто выплюнь всё, что есть в голове. 1000 слов мусора — лучше, чем 0 слов идеального.

**Шаг 1: структурная редактура**

```
Вот мой грязный черновик. Найди в нём 3-5 ключевых идей.
Перестрой текст так, чтобы каждая идея была в отдельном блоке.
Не переписывай — просто перемести абзацы. Покажи новую структуру.
```

**Шаг 2: чистка**

```
В тексте много повторений, воды и ходений по кругу.
Убери всё лишнее. Оставь только то, без чего смысл ломается.
Не добавляй ничего нового. Только удаляй.
```

**Шаг 3: усиление**

```
Теперь текст стал сухим. Добавь:
- Один яркий пример, который иллюстрирует главную мысль
- Один контраргумент и его опровержение
- Один риторический вопрос, который заставит читателя остановиться

Не переписывай всё — только добавь эти элементы.
```

**Шаг 4: заголовки и вступление**

```
Этот текст потерял цепляющее начало. Напиши:
- 5 вариантов заголовка (короткий, провокационный, вопросительный, с цифрой, безэмоциональный)
- 3 варианта вступления (с историей, с фактом, с вопросом)

Я выберу, а ты встроишь выбранное.
```

**Шаг 5: финальная проверка**

```
Прочитай текст целиком. Скажи одно предложение:
что здесь самое сильное и что самое слабое?
Одно предложение для каждого.
```

**Почему 5 шагов, а не один запрос «сделай идеально»?**

Потому что когда ты просишь ИИ «сделай идеально», он делает всё сразу — но поверхностно. Когда ты делаешь 5 отдельных шагов, каждый раз ИИ концентрируется на одной задаче, и результат каждого шага глубже.

5 отдельных запроса → результат лучше, чем 1 запрос с 10 параметрами.

## Быстрая шпаргалка: какой сценарий использовать

| Ситуация | Инструмент |
|---|---|
| Не знаю, что хочу | Метакognition — задай вопросы |
| Есть черновик | Итеративная редактура (5 шагов) |
| Есть черновик и время на одну итерацию | Редакторская критика |
| Есть два текста | Сравнение + склейка |
| Есть один текст и 5 платформ | Адаптация под платформы |
| Текст длиннее 20 сообщений | Новый чат + контекстное окно |
| В тексте есть данные людей | Анонимизация |
| Текст должен выдержать критику | Актор-критик цикл |
| Не доверяю ответу ИИ | Веб-поиск + проверка источников |

## Финальная мысль

Лучший способ работать с ИИ — не запоминать промпты, а понимать принцип:

**ИИ не думает. Он реагирует.**

Чем конкретнее ты формулируешь реакцию — тем точнее ответ. Чем больше контекста даёшь — тем лучше результат. Чем честнее говоришь, что не знаешь — тем полезнее ИИ поможет это узнать.

И помни: лучший текст — не тот, который ИИ написал за тебя. А тот, который ты написал сам, с помощью ИИ.
